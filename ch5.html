5.1 Introduction to Pushdown Automata
5.1.1 What is a PDA?
Definition

A Pushdown Automaton (PDA) = Finite State Machine + an Infinite Stack. The stack gives it the ability to store and retrieve unlimited information, making it more powerful than FA.

Figure 5.1 — PDA Architecture: Finite Control reads input tape and operates on a Stack (push/pop). Stack is LIFO — top is leftmost in notation.
FA vs PDA
  • FA: Only states — finite memory
  • PDA: States + infinite stack
  • FA cannot count aⁿbⁿ — no memory for n
  • PDA can: push n A's, pop n A's
  • PDA = FA + stack → more power
Why PDA?
  • Accepts exactly Context Free Languages
  • Models syntax analysis in compilers
  • Handles nested structures (parens, tags)
  • Used in LL/LR parsers
  • Every CFL has an equivalent PDA
5.1.2 Formal Definition — 7-Tuple
PDA — 7-Tuple

A Pushdown Automaton is formally defined as: M = (Q, Σ, Γ, δ, q₀, Z₀, F)

Symbol Name Description Example
Q States Finite, non-empty set of all states {q0, q1, q2}
Σ Input Alphabet Finite set of input symbols {a, b}
Γ Stack Alphabet Finite set of symbols that can appear on the stack. Γ ⊇ Σ typically. {A, Z₀}
δ Transition Function δ: Q × (Σ∪{ε}) × Γ → finite subsets of Q × Γ* δ(q0,a,Z0)={(q0,aZ0)}
q₀ Start State Initial state. q₀ ∈ Q q0
Z₀ Initial Stack Symbol Symbol initially on the bottom of the stack. Z₀ ∈ Γ Z₀ or $
F Final States Set of accepting states. F ⊆ Q (can be empty for empty stack acceptance) {q2}
5.1.3 Transition Function δ in Detail
δ(q, a, X) = {(p₁, γ₁), (p₂, γ₂), ...}
Part Meaning
q Current state
a Input symbol being read (or ε for empty move — no input consumed)
X Current top symbol of the stack
p Next state to move to
γ String to replace X on top of stack (γ ∈ Γ*). Left end = top of stack.
5.1.4 Stack Operations Explained
Operation Meaning δ notation Example
PUSH 'a' Add 'a' on top. X stays below. δ(q, ?, X) = (p, aX) Stack X → Stack aX (a on top)
POP Remove top symbol X. δ(q, ?, X) = (p, ε) Stack aX → Stack X
NO-OP Leave stack unchanged. δ(q, ?, X) = (p, X) Stack stays same
REPLACE Replace top X with Y. δ(q, ?, X) = (p, Y) Stack X → Stack Y
PUSH 3 symbols Push AAA on top of X. δ(q, ?, X) = (p, AAAX) Stack X → Stack AAAX
Stack Convention — TOP is LEFTMOST

In PDA notation, the stack contents are written with the TOP on the LEFT. So if we write "aZ₀", it means 'a' is on top and Z₀ is at the bottom. Pushing 'a' onto a stack with Z₀ → write "aZ₀".

5.2 Instantaneous Description (ID)
5.2.1 ID Triple — (q, w, α)
Definition

An Instantaneous Description (ID) is a snapshot of the PDA at any point during computation. It captures everything needed to continue the computation.

ID = (q, w, α)
Component Meaning Example
q Current state of the PDA q0, q1
w Remaining input string (yet to be read) "bb" (means 'b' and 'b' still to process)
α Current stack contents — TOP on LEFT "aaZ₀" means 2 a's on stack with Z₀ at bottom
5.2.2 Turnstile Notation
Notation

The symbol ⊢ (turnstile) represents ONE move of the PDA. ⊢* represents zero or more moves.

(q, aw, Xβ) ⊢ (p, w, γβ)
Reading the Turnstile Notation
  • q = current state, p = next state
  • a = input symbol consumed (or ε if no input consumed)
  • w = remaining input AFTER consuming 'a'
  • X = stack top symbol popped/replaced
  • β = rest of stack below X (stays unchanged)
  • γ = new string pushed on stack in place of X
  • Condition: δ(q, a, X) must contain (p, γ)
Example ID Trace — aⁿbⁿ PDA for input "aabb"
Step Current ID (state, input, stack) Move / Action
Start (q0, aabb, Z₀) Initial configuration
1 ⊢ (q0, abb, aZ₀) Read 'a', push 'a' on Z₀
2 ⊢ (q0, bb, aaZ₀) Read 'a', push another 'a'
3 ⊢ (q1, b, aZ₀) Read 'b', pop 'a', change to q1
4 ⊢ (q1, ε, Z₀) Read 'b', pop 'a'
5 ⊢ (q2, ε, ε) ε-move, pop Z₀ → ACCEPT ✓

Written compactly: (q0,aabb,Z₀) ⊢ (q0,abb,aZ₀) ⊢ (q0,bb,aaZ₀) ⊢ (q1,b,aZ₀) ⊢ (q1,ε,Z₀) ⊢ (q2,ε,ε)

5.3 Language Acceptance by PDA
Acceptance by FINAL STATE
  • PDA must reach a state in F after consuming all input.
  • Stack content = doesn't matter (can be anything).
  • Formula: (q₀, w, Z₀) ⊢* (qf, ε, γ) for some qf ∈ F, any γ
  • F must be non-empty.
  • More common in theoretical definitions.
Acceptance by EMPTY STACK
  • PDA must empty its stack completely after consuming all input.
  • Final state = doesn't matter (any state is fine).
  • Formula: (q₀, w, Z₀) ⊢* (q, ε, ε) for some q
  • F can be empty set ∅.
  • Simpler to design PDAs for this.
5.3.1 Equivalence of Both Acceptance Methods
Theorem — Both Methods Are Equivalent
  • A language L is accepted by final state PDA ↔ L is accepted by empty stack PDA.
  • Empty Stack → Final State: Add new final state qf. From any state when stack has only Z₀, add ε-transition to qf.
  • Final State → Empty Stack: From every state qf ∈ F, add ε-transitions that pop all remaining stack symbols until empty.
Comparison for L = {aⁿbⁿ | n ≥ 1}

Final State version: After matching all pairs, ε-transition from q1 to q2 (final state) when Z₀ is on top.

Empty Stack version: After matching all pairs, pop Z₀ too. No need for q2 — accept when stack empty in q1.

Both accept exactly the same strings "ab", "aabb", "aaabbb", ...

P1
PDA for L = {aⁿbⁿ | n ≥ 1}
Language: equal number of a's followed by equal number of b's. e.g. ab, aabb, aaabbb

Strategy: Push one 'A' for each 'a' read. Pop one 'A' for each 'b' read. Accept when stack is empty (only Z₀).

FINAL STATE VERSION — F = {q2}

δ(q0, a, Z₀) = (q0, AZ₀) // push A on Z₀
δ(q0, a, A) = (q0, AA) // push another A
δ(q0, b, A) = (q1, ε) // pop A, switch phase
δ(q1, b, A) = (q1, ε) // continue popping
δ(q1, ε, Z₀) = (q2, Z₀) // reach final state q2

EMPTY STACK VERSION — F = ∅

δ(q0, a, Z₀) = (q0, AZ₀) // push A
δ(q0, a, A) = (q0, AA) // push A
δ(q0, b, A) = (q1, ε) // pop A
δ(q1, b, A) = (q1, ε) // pop A
δ(q1, ε, Z₀) = (q1, ε) // pop Z₀ → empty!

P2
PDA for L = {aⁿcbⁿ | n ≥ 1}
Language: n a's, then single 'c', then n b's. e.g. acb, aacbb, aaacbbb

Strategy: Push 'A' for each 'a'. The 'c' in the middle is the separator — switch states on 'c' without changing the stack. Pop 'A' for each 'b'.

δ(q0, a, Z₀) = (q0, AZ₀) // push A, first 'a'
δ(q0, a, A) = (q0, AA) // push A, more 'a's
δ(q0, c, A) = (q1, A) // read 'c', switch state, KEEP stack
δ(q1, b, A) = (q1, ε) // pop A for each 'b'
δ(q1, ε, Z₀) = (q2, Z₀) // accept when matched
ID Trace — "aacbb"

(q0, aacbb, Z₀) ⊢ (q0, acbb, AZ₀) ⊢ (q0, cbb, AAZ₀) ⊢ (q1, bb, AAZ₀) ⊢ (q1, b, AZ₀) ⊢ (q1, ε, Z₀) ⊢ (q2, ε, Z₀) ACCEPT

P3
PDA for L = {0ᵐ1ⁿ2ⁿ | m, n ≥ 0}
Language: any 0s, then equal 1s and 2s. e.g. ε, 00, 12, 1122, 001122

Strategy: Ignore 0s (no stack operation). Push 'A' for each '1'. Pop 'A' for each '2'. Accept when stack has only Z₀ after all 2s.

δ(q0, 0, Z₀) = (q0, Z₀) // skip 0s, no stack change
δ(q0, ε, Z₀) = (q1, Z₀) // skip to 1-phase (handles m=0)
δ(q1, 1, Z₀) = (q1, AZ₀) // push A for first 1
δ(q1, 1, A) = (q1, AA) // push A for more 1s
δ(q1, 2, A) = (q2, ε) // pop A for each 2
δ(q2, 2, A) = (q2, ε) // continue popping
δ(q2, ε, Z₀) = (q3, Z₀) // accept when 1s = 2s
δ(q1, ε, Z₀) = (q3, Z₀) // accept n=0 (no 1s or 2s)
Design Note
  • The key insight: 0s are ignored — they don't affect the 1-2 counting.
  • The ε-transition from q0 to q1 handles the case m=0 (no 0s).
  • The ε-transition from q1 to q3 with Z₀ handles n=0 (no 1s or 2s, so empty second part).
P4
PDA for L = {aⁿb³ⁿ | n ≥ 1}
Language: n a's followed by 3n b's. e.g. abbb, aabbbbbb, aaabbbbbbbbb

Strategy: For each 'a', push 3 markers onto the stack. For each 'b', pop one marker. Since each transition only pushes one symbol, we use intermediate states to push 3 per 'a'.

// For each 'a', use 3 intermediate states to push 3 A's:
δ(q0, a, Z₀) = (q1, AZ₀) // read 'a', push 1st A
δ(q1, ε, A) = (q2, AA) // ε-move, push 2nd A
δ(q2, ε, A) = (q0, AA) // ε-move, push 3rd A, back to q0
δ(q0, a, A) = (q1, AA) // another 'a', push 1st A of next group
// After all a's, pop one A per b:
δ(q0, b, A) = (q3, ε) // first 'b', pop A, switch to q3
δ(q3, b, A) = (q3, ε) // continue popping
δ(q3, ε, Z₀) = (q4, Z₀) // accept
Trace — "abbb" (n=1, 3n=3)

q0 → read 'a' → q1 (push 1st A: AZ₀) → ε → q2 (push 2nd A: AAZ₀) → ε → q0 (push 3rd A: AAAZ₀) → read 'b' → q3 (pop: AAZ₀) → read 'b' → q3 (pop: AZ₀) → read 'b' → q3 (pop: Z₀) → ε → q4 ACCEPT

P5
PDA for L = {w ∈ {a,b}* | #a(w) = #b(w)}
Language: strings with equal number of a's and b's. e.g. ε, ab, ba, aabb, abba, baba

Strategy: Track "excess" symbols. Stack shows imbalance — if more a's seen, stack has A's; if more b's, stack has B's. When a cancels a B (or b cancels an A), pop.

// More a's than b's so far — A's on stack:
δ(q0, a, Z₀) = (q0, AZ₀) // first a
δ(q0, a, A) = (q0, AA) // more a's: push A
δ(q0, b, A) = (q0, ε) // b cancels one a: pop A
// More b's than a's so far — B's on stack:
δ(q0, b, Z₀) = (q0, BZ₀) // first b
δ(q0, b, B) = (q0, BB) // more b's: push B
δ(q0, a, B) = (q0, ε) // a cancels one b: pop B
// Accept when equal (stack has only Z₀):
δ(q0, ε, Z₀) = (q1, Z₀) // equal count → accept
Trace — "baba"

(q0,baba,Z₀) ⊢ (q0,aba,BZ₀) ⊢ (q0,ba,Z₀) ⊢ (q0,a,BZ₀) ⊢ (q0,ε,Z₀) ⊢ (q1,ε,Z₀) ACCEPT

P6
PDA for L = {wwᴿ | w ∈ {a,b}*} — Even Palindromes
Language: strings that read the same forwards and backwards (even length). e.g. ε, abba, baab, aabbaa

Strategy: This requires nondeterminism. Push all symbols in the first half, then guess the midpoint and match/pop symbols in the second half.

// PUSH phase — push every symbol read:
δ(q0, a, Z₀) = {(q0, aZ₀)} // push a
δ(q0, b, Z₀) = {(q0, bZ₀)} // push b
δ(q0, a, a) = {(q0, aa)} // push a on top of a
δ(q0, a, b) = {(q0, ab)} // push a on top of b
δ(q0, b, a) = {(q0, ba)} // push b on top of a
δ(q0, b, b) = {(q0, bb)} // push b on top of b
// GUESS middle (nondeterministic switch — ε-transition):
δ(q0, ε, a) = {(q1, a)} // guess: we're at midpoint
δ(q0, ε, b) = {(q1, b)} // guess: midpoint
δ(q0, ε, Z₀) = {(q1, Z₀)} // guess: empty string midpoint
// POP/MATCH phase — match input with stack:
δ(q1, a, a) = {(q1, ε)} // match 'a' with top 'a'
δ(q1, b, b) = {(q1, ε)} // match 'b' with top 'b'
δ(q1, ε, Z₀) = {(q2, ε)} // stack empty → ACCEPT
Why Nondeterminism is Needed

A deterministic PDA (DPDA) cannot recognize the language of all palindromes. The PDA must "guess" when it has reached the midpoint of the input — there's no way to know deterministically. This is a classic example where NPDA is strictly more powerful than DPDA.

Trace — "abba"

q0 push 'a': (q0,abba,Z₀)⊢(q0,bba,aZ₀) → push 'b': (q0,ba,baZ₀) → guess middle with ε: (q1,ba,baZ₀) → match 'b': (q1,a,aZ₀) → match 'a': (q1,ε,Z₀) → accept: (q2,ε,ε) ACCEPT

P7
PDA for L = {abⁿacabⁿa | n ≥ 0}
Language: a(b*)a c a(b*)a where both b-runs have equal length. e.g. aaca (n=0), ababcaba... wait: abacaba (n=1)

Structure: a · bⁿ · a · c · a · bⁿ · a. Push B for each 'b' in first group, pop B for each 'b' in second group.

δ(q0, a, Z₀) = (q1, Z₀) // read first 'a'
δ(q1, b, Z₀) = (q1, BZ₀) // push B for b's (n=0 case: no b's)
δ(q1, b, B) = (q1, BB) // push more B's
δ(q1, a, Z₀) = (q2, Z₀) // read 'a' after b's (n=0: stack=Z₀)
δ(q1, a, B) = (q2, B) // read 'a' after b's (keep stack)
δ(q2, c, B) = (q3, B) // read 'c' separator
δ(q2, c, Z₀) = (q3, Z₀) // read 'c' (n=0 case)
δ(q3, a, B) = (q4, B) // read 'a' after 'c'
δ(q3, a, Z₀) = (q4, Z₀) // read 'a' (n=0)
δ(q4, b, B) = (q4, ε) // pop B for each matched 'b'
δ(q4, a, Z₀) = (q5, ε) // read final 'a' → accept
P8
PDA for L = {aⁱbʲcᵏ | i, j, k ≥ 0 and i + j = k}
Language: a's and b's combined count equals c's count. e.g. ε, c, ac, bc, aaabcc (i=1,j=0,k=1)

Strategy: Push one marker (X) for each 'a' and each 'b'. Pop one X for each 'c'. Accept when stack is empty.

// Phase 1: Push X for every 'a':
δ(q0, a, Z₀) = (q0, XZ₀) // push X for a
δ(q0, a, X) = (q0, XX) // push X for more a's
// Phase 2: Push X for every 'b' (switch to q1):
δ(q0, b, Z₀) = (q1, XZ₀) // first b (no a's before)
δ(q0, b, X) = (q1, XX) // first b (after a's)
δ(q1, b, X) = (q1, XX) // push X for more b's
δ(q1, b, Z₀) = (q1, XZ₀) // push X (no prev symbols)
// Phase 3: Pop X for every 'c':
δ(q0, c, X) = (q2, ε) // start popping (no b's case)
δ(q1, c, X) = (q2, ε) // start popping (after b's)
δ(q2, c, X) = (q2, ε) // continue popping
δ(q2, ε, Z₀) = (q3, Z₀) // accept: i+j = k
// Edge cases:
δ(q0, ε, Z₀) = (q3, Z₀) // accept ε (i=j=k=0)
δ(q1, ε, Z₀) = (q3, Z₀) // accept: all a's+b's, zero c's → only if i+j=0
P9
PDA for L = {aⁿbᵐcᵐdⁿ | n, m ≥ 0}
Language: n a's, m b's, m c's, n d's. Matches a-d and b-c pairs. e.g. ε, ad, bc, abcd, aabcdd

Strategy: Push 'A' for each 'a'. Push 'B' for each 'b'. Pop 'B' for each 'c'. Pop 'A' for each 'd'. Stack ensures both counts match.

δ(q0, a, Z₀) = (q0, AZ₀) // push A for a's
δ(q0, a, A) = (q0, AA) // push more A's
δ(q0, b, A) = (q1, BA) // switch: push B on top of A
δ(q0, b, Z₀) = (q1, BZ₀) // push B (n=0 case)
δ(q1, b, B) = (q1, BB) // push more B's
δ(q1, c, B) = (q2, ε) // pop B for each 'c'
δ(q2, c, B) = (q2, ε) // continue popping B's
δ(q2, d, A) = (q3, ε) // pop A for each 'd'
δ(q3, d, A) = (q3, ε) // continue popping A's
δ(q3, ε, Z₀) = (q4, Z₀) // accept
// Handles n=0 and m=0 cases:
δ(q0, ε, Z₀) = (q4, Z₀) // accept ε
δ(q0, c, A) = (q2, A) // m=0: no b's, go to c phase
Trace — "aabcdd" (n=2, m=1)

(q0,aabcdd,Z₀) ⊢ (q0,abcdd,AZ₀) ⊢ (q0,bcdd,AAZ₀) ⊢ (q1,cdd,BAAZ₀) ⊢ (q2,dd,AAZ₀) ⊢ (q3,d,AZ₀) ⊢ (q3,ε,Z₀) ⊢ (q4,ε,Z₀) ACCEPT

P10
PDA for Language of Balanced Parentheses
Language: Σ = {(, )}. e.g. ε, (), (()), ()(), ((())), (()())

Strategy: Push '(' onto stack for every '(' read. Pop when we see ')'. Accept when stack is empty after all input.

δ(q0, (, Z₀) = (q0, (Z₀) // push '(' on Z₀
δ(q0, (, () = (q0, (() // push another '('
δ(q0, ), () = (q0, ε) // ')' matches '(': pop
δ(q0, ε, Z₀) = (q1, Z₀) // empty stack → balanced → accept
Trace — "(())"

(q0,(()),Z₀) ⊢ (q0,()), (Z₀) ⊢ (q0,)), ((Z₀) ⊢ (q0,), (Z₀) ⊢ (q0,ε,Z₀) ⊢ (q1,ε,Z₀) ACCEPT

String "()" fails: (q0,(,Z₀) ⊢ (q0,,Z₀)... wait stack has '('. On ')' pop. Stack = Z₀. Accept ✓

String ")(": (q0,)(,Z₀) — δ(q0, ), Z₀) = undefined → REJECT

5.5 Power of PDA over FSM
Capability FA (DFA/NFA) DPDA NPDA
Count arbitrarily ✗ No ✓ Yes ✓ Yes
Match aⁿbⁿ ✗ No ✓ Yes ✓ Yes
Match nested structures ✗ No ✓ Yes ✓ Yes
Recognize all palindromes ✗ No ✗ No ✓ Yes
Recognize regular languages ✓ Yes ✓ Yes ✓ Yes
Recognize aⁿbⁿcⁿ ✗ No ✗ No ✗ No
Memory type Finite (states) Stack (LIFO) Stack (LIFO)
Memory size Finite Infinite (stack) Infinite (stack)
Figure 5.3 — Language Hierarchy. Regular ⊂ DCFL ⊂ CFL ⊂ CSL. Each level adds expressive power.
Key Relationships
  • Every Regular Language is a CFL. PDA can simulate any DFA (just ignore the stack).
  • aⁿbⁿ is CFL but NOT Regular — proves PDA is strictly more powerful than FA.
  • Palindromes are CFL (via NPDA) but NOT recognizable by DPDA — NPDA is strictly more powerful than DPDA.
  • aⁿbⁿcⁿ is NOT a CFL — proves PDA cannot do everything; Turing Machines are needed.
5.6 CFG to PDA Conversion
Theorem

Every CFG has an equivalent NPDA, and every NPDA has an equivalent CFG. The conversion is mechanical and straightforward.

CFG → PDA Conversion Algorithm (Top-Down Parsing)
  • Create a PDA with states: q_start, q_loop, q_accept.
  • Step 1: δ(q_start, ε, Z₀) = (q_loop, SZ₀) — push the start symbol S.
  • Step 2: For each production A → α in the CFG: add δ(q_loop, ε, A) = (q_loop, α) — replace A on stack with α.
  • Step 3: For each terminal 'a': add δ(q_loop, a, a) = (q_loop, ε) — if stack top matches input, pop both.
  • Step 4: δ(q_loop, ε, Z₀) = (q_accept, Z₀) — accept when stack is empty.
Example — CFG S → aSa | bSb | ε converted to PDA

CFG productions: S → aSa | bSb | ε

δ(q_s, ε, Z₀) = (q_loop, SZ₀) // push start symbol S
// Production S → aSa:
δ(q_loop, ε, S) = (q_loop, aSa) // expand S → aSa
// Production S → bSb:
δ(q_loop, ε, S) = (q_loop, bSb) // expand S → bSb
// Production S → ε:
δ(q_loop, ε, S) = (q_loop, ε) // expand S → ε (pop S)
// Terminal matches:
δ(q_loop, a, a) = (q_loop, ε) // match 'a'
δ(q_loop, b, b) = (q_loop, ε) // match 'b'
δ(q_loop, ε, Z₀)= (q_acc, Z₀) // accept

This PDA simulates leftmost derivation of the CFG. When a non-terminal is on top of the stack, it's expanded (ε-transition). When a terminal is on top and matches input, both are consumed.

5.7 Practice Questions
PDA Design Questions
1

Design a PDA for L = {aⁿb²ⁿ | n ≥ 1}. Show transitions and trace for "abbb" (n=1).

Strategy: Push 2 markers (AA) for each 'a'. Pop one A per 'b'.
δ(q0,a,Z₀) = (q1,AZ₀); δ(q1,ε,A) = (q0,AA) — push 2nd A; δ(q0,a,A) = (q1,AA) for more a's;
δ(q0,b,A) = (q2,ε); δ(q2,b,A) = (q2,ε); δ(q2,ε,Z₀) = (q3,Z₀) accept.
Trace "abbb": (q0,abbb,Z₀)⊢(q1,bbb,AZ₀)⊢(q0,bbb,AAZ₀)⊢(q2,bb,AZ₀)⊢(q2,b,Z₀)⊢... wait, only 2 A's popped by 2 b's, but input has 3 b's. n=1: a·b·b·b = "abbb" means 3 b's but 2n=2. So "abb" is correct for n=1. For "abbb" n must be 1.5 which is invalid → REJECT.
2

Design a PDA for L = {wcwᴿ | w ∈ {a,b}*}. What's the difference from Problem P6 (palindromes wwᴿ)?

Strategy: Push all symbols before 'c'. After 'c', pop and match. No nondeterminism needed — 'c' is the deterministic separator.
δ(q0,a,Z₀)=(q0,aZ₀); δ(q0,b,Z₀)=(q0,bZ₀); δ(q0,a,a)=(q0,aa); δ(q0,a,b)=(q0,ab) etc.
δ(q0,c,a)=(q1,a); δ(q0,c,b)=(q1,b); δ(q0,c,Z₀)=(q1,Z₀) — switch on 'c'.
δ(q1,a,a)=(q1,ε); δ(q1,b,b)=(q1,ε); δ(q1,ε,Z₀)=(q2,Z₀) accept.
Key Diff: wcwᴿ → DPDA (deterministic — 'c' tells us midpoint). wwᴿ → NPDA only (must guess midpoint).
3

Design a PDA for L = {aⁿbᵐ | n ≠ m, n, m ≥ 0}.

Strategy: n ≠ m means either n > m OR n < m. Union of two cases.
Case 1 (n > m): Push A for each 'a'. Pop A for each 'b'. Accept if stack still has A's left after all b's.
Case 2 (n < m): Push A for each 'a'. Pop A for each 'b'. Accept if stack goes empty before all b's are read.
Both branches run nondeterministically. δ(q0,a,Z₀)=(q0,AZ₀); δ(q0,a,A)=(q0,AA); δ(q0,b,A)=(q1,ε); δ(q1,b,A)=(q1,ε);
Case 1: δ(q1,ε,A)=(q2,A) accept (A's remain → more a's). Case 2: δ(q1,b,Z₀)=(q1,Z₀)... need 'b' remaining after stack empty.
4

Convert CFG G: S → aSb | ε to an equivalent PDA and trace "aaabbb".

PDA (3-state, top-down):
δ(q0,ε,Z₀)=(q1,SZ₀) — init push S.
δ(q1,ε,S)=(q1,aSb) — expand S→aSb.
δ(q1,ε,S)=(q1,ε) — expand S→ε (pop S).
δ(q1,a,a)=(q1,ε) — match 'a'. δ(q1,b,b)=(q1,ε) — match 'b'.
δ(q1,ε,Z₀)=(q2,Z₀) — accept.
Trace "aabb": Push S → expand S→aSb: stack=aSbZ₀ → match a: stack=SbZ₀ → expand S→aSb: aSbbZ₀ → match a: SbbZ₀ → expand S→ε: bbZ₀ → match b: bZ₀ → match b: Z₀ → accept ✓
5

Construct a PDA for L = {w | w ∈ {a,b}*, na(w) = 2×nb(w)} — a's are twice the b's.

Strategy: For each 'b', push 2 A's. For each 'a', pop 1 A. Accept when stack empty.
δ(q0,b,Z₀)=(q0,AAZ₀); δ(q0,b,A)=(q0,AAA) — push 2 A's per b;
δ(q0,a,A)=(q0,ε) — pop 1 A per a;
δ(q0,ε,Z₀)=(q1,Z₀) — accept when balanced.
Example: "aab" — push 2A (b): AAZ₀ → pop 1A (a): AZ₀ → pop 1A (a): Z₀ → accept ✓ (2 a's = 2×1 b)
Theory Questions
6

What are the two methods of acceptance by PDA? Write their formal definitions and explain the difference.

1. Final State: L(M) = {w | (q0,w,Z₀) ⊢* (qf,ε,γ) for some qf ∈ F, any stack γ}. PDA reaches a final state; stack content doesn't matter.
2. Empty Stack: N(M) = {w | (q0,w,Z₀) ⊢* (q,ε,ε) for any state q}. Stack is completely empty; final state doesn't matter.
Difference: Final state focuses on which state we end in; empty stack focuses on having emptied the stack. Both methods are equivalent in power.
7

Prove that every Regular Language is a CFL (i.e., every DFA can be simulated by a PDA).

Construction: Given DFA M = (Q, Σ, δ_FA, q0, F), construct PDA M' = (Q, Σ, {Z₀}, δ_PDA, q0, Z₀, F) where:
For every DFA transition δ_FA(q,a)=p, add PDA transition δ_PDA(q,a,Z₀)={(p,Z₀)} — state changes same as DFA, stack never changes (just keep Z₀).
The PDA ignores its stack completely and behaves exactly like the DFA.
Result: L(M') = L(M). Since every Regular Language has a DFA, every Regular Language has a PDA → every RL is a CFL. RL ⊂ CFL □
8

Explain why NPDA can recognize palindromes but DPDA cannot. Give a formal argument.

NPDA: Uses ε-transitions to nondeterministically guess the midpoint of the string. At any point, it can switch from push-phase to match-phase. Since at least one branch will guess correctly, the NPDA accepts all palindromes.
DPDA cannot: A DPDA must make deterministic choices. For string "abba", when reading 'a', it cannot know if this 'a' is the first character of "abba" (which should be pushed) or if it's being confirmed after "abb". There's no way to deterministically identify the midpoint without seeing all input — but stack isn't reversible. Formal proof uses the fact that language of all even palindromes is not a Deterministic CFL.
9

Why can't a PDA recognize L = {aⁿbⁿcⁿ | n ≥ 1}?

Proof using Pumping Lemma for CFLs:
Assume L is a CFL with pumping length p. Choose w = aᵖbᵖcᵖ ∈ L (|w| = 3p ≥ p).
Split w = uvxyz with |vy| ≥ 1 and |vxy| ≤ p.
Since |vxy| ≤ p, the substring vxy spans at most 2 types of symbols (can't span all three types a, b, c simultaneously).
Pumping (i=2): uv²xy²z has more of 1-2 symbol types but not all three equally.
So uv²xy²z ∉ L → contradiction. L is NOT a CFL → PDA cannot recognize it. □
Intuition: The stack is LIFO — you can match a's with b's OR b's with c's, but not both simultaneously.

Concept Key Fact
PDA = ? Finite State Machine + Infinite Stack (LIFO). 7-tuple: (Q, Σ, Γ, δ, q₀, Z₀, F)
7-Tuple Q=states, Σ=input alphabet, Γ=stack alphabet, δ=transition, q₀=start, Z₀=initial stack, F=final states
Transition δ δ: Q×(Σ∪{ε})×Γ → finite subsets of Q×Γ*. Maps (state, input/ε, stack-top) → (next-state, new-stack-top)
Stack notation TOP is on the LEFT. "aZ₀" = 'a' on top, Z₀ at bottom. Push 'a' onto Z₀ → "aZ₀".

POP δ(q,a,X) = (p, ε) — remove X (stack shrinks)
NO-OP δ(q,a,X) = (p, X) — X remains on top
ID Triple (q, w, α) = current state, remaining input, stack contents (top-left)
Turnstile ⊢ One PDA move. ⊢* = zero or more moves.
Final State acceptance (q₀,w,Z₀) ⊢* (qf,ε,γ) for qf ∈ F. Stack content doesn't matter.
Empty Stack acceptance (q₀,w,Z₀) ⊢* (q,ε,ε). Final state doesn't matter. Stack must be empty.
Both equivalent Final state ≡ Empty stack. Can convert between them.
aⁿbⁿ PDA Push A for each 'a'. Pop A for each 'b'. Accept on empty stack.
Equal a's & b's Push A (excess a), push B (excess b), pop on opposite symbol. Accept when Z₀ only.
Palindromes Nondeterministically guess middle. Push first half, match+pop second half.
wcwᴿ Push before 'c'. Match+pop after 'c'. Deterministic (DPDA possible).
i+j=k Push X for each a and b. Pop X for each c.
aⁿbᵐcᵐdⁿ Push A for a's. Push B for b's (on top of A's). Pop B for c's. Pop A for d's.
NPDA > DPDA Palindromes: NPDA yes, DPDA no. Every DPDA is a NPDA, not vice versa.
PDA > FA aⁿbⁿ: PDA yes, FA no. Every FA is a PDA (ignore stack). Not vice versa.
PDA cannot do aⁿbⁿcⁿ (needs LBA/TM). Any language requiring TWO stacks simultaneously.
CFG → PDA 3 states. Push start symbol. For each production A→α: ε-transition replaces A on stack with α. For each terminal: pop when matched.
🎯 Exam Must-Remember
  • PDA is 7-tuple — not 5-tuple like DFA. Extra components: Γ (stack alphabet) and Z₀ (initial stack symbol).
  • Stack TOP is on the LEFT in all notation. "aZ₀" = a is on top.
  • Push: δ(q,a,X) = (p, newX) where new has MORE symbols. Pop: δ(q,a,X) = (p, ε) — replaces X with nothing.
  • ID trace format: (state, remaining-input, stack-top-to-bottom). Show every ⊢ step.
  • Final state acceptance: stack can have anything. Empty stack acceptance: stack must be completely empty.
  • aⁿbⁿ: classic PDA — push for a's, pop for b's. 2 states + final.
  • Equal a's & b's: need TWO marker types (A and B) to track excess of either.
  • wcwᴿ (DPDA) vs wwᴿ (NPDA only) — KNOW this distinction!
  • aⁿbᵐcᵐdⁿ: push A's then B's, pop B's for c's, pop A's for d's. Stack order matters.
  • CFG → PDA: push start symbol S, ε-expand non-terminals, match+pop terminals.
