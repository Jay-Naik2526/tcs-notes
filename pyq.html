Q1a
Ambiguous Grammar & Testing
[5]
What is ambiguous grammar? Test the following grammar G for ambiguity, and if G is ambiguous, what is the cause of ambiguity?
G = {E, (+,*,a), {E → E+E, E → E*E, E → a}, E}
Definition

An Ambiguous Grammar is a Context-Free Grammar (CFG) for which there exists at least one string in its language that can be generated by more than one distinct leftmost derivation (or equivalently, has more than one distinct parse tree).

Testing for Ambiguity

Let us test the string w = a + a * a

Parse Tree 1 (Leftmost derivation prioritizing '+'): E ⇒ E + E ⇒ a + E ⇒ a + E * E ⇒ a + a * E ⇒ a + a * a Parse Tree 2 (Leftmost derivation prioritizing '*'): E ⇒ E * E ⇒ E + E * E ⇒ a + E * E ⇒ a + a * E ⇒ a + a * a

Since the string a + a * a has two distinct leftmost derivations (and two distinct parse trees), the grammar G is ambiguous.

Cause of Ambiguity

The primary cause of ambiguity in this grammar is the lack of precedence and associativity rules. Both '+' and '*' are treated at the same hierarchical level of production (E → E+E and E → E*E), allowing the parser to arbitrarily choose which operation to bind first.

To construct a PDA from a given CFG, we use top-down parsing (simulating leftmost derivation on the stack). We start by pushing the start symbol 'S'. Q1c
Turing Machine vs Mealy Machine
[5]
Give Formal Definition of Turing Machine & Mealy Machine. How they are different from each other.
Formal Definition: Turing Machine (7-tuple)

A Turing Machine is formally defined as M = (Q, Σ, Γ, δ, q₀, B, F) where:

  • Q: Finite set of states.
  • Σ: Finite set of input symbols (excluding Blank).
  • Γ: Finite set of tape symbols (Σ ⊆ Γ).
  • δ: Transition function (Q × Γ → Q × Γ × {L, R}).
  • q₀: Initial start state (q₀ ∈ Q).
  • B: Blank symbol (B ∈ Γ, but B ∉ Σ).
  • F: Set of final or accepting states (F ⊆ Q).
Formal Definition: Mealy Machine (6-tuple)

A Mealy Machine is formally defined as M = (Q, Σ, Δ, δ, λ, q₀) where:

  • Q: Finite set of states.
  • Σ: Finite set of input alphabet.
  • Δ: Finite set of output alphabet.
  • δ: Transition function mapping current state and input to next state (Q × Σ → Q).
  • λ: Output function mapping current state and input to output (Q × Σ → Δ).
  • q₀: Initial start state (q₀ ∈ Q).

Q1d
Applications of RE and Grammar
[5]
What are the applications of Regular Expression and Grammar in Compiler Constructions? Explain.
1. Regular Expressions (Lexical Analysis)

In the very first phase of compilation, called Lexical Analysis (or scanning), the compiler reads the raw source code character by character and groups them into meaningful units called tokens (e.g., keywords, identifiers, constants, operators).
Application: Regular expressions are used to formally specify the patterns for these tokens. For example, an identifier might be defined as [a-zA-Z][a-zA-Z0-9]*. The compiler generator tools (like Lex or Flex) automatically convert these regular expressions into a Deterministic Finite Automaton (DFA) which efficiently scans the code and returns matched tokens.

2. Context-Free Grammars (Syntax Analysis)

In the second phase, called Syntax Analysis (or parsing), the compiler receives the stream of tokens from the lexical analyzer and verifies if they form a valid structural sequence according to the language rules.
Application: Context-Free Grammars (CFG) are used to define the hierarchical, recursive syntax of programming languages. For example, a grammar rule might specify: Stmt → if (Expr) Stmt else Stmt. Tools like Yacc or Bison take these CFG rules and automatically generate Pushdown Automata (PDA) based parsers (such as LALR parsers) that construct the Abstract Syntax Tree (AST).

Formal Turing Machine (7-tuple)

M = (Q, Σ, Γ, δ, q₀, B, F)

  • Q: {q0, q1, q2, q3, q4, q_acc}
  • Σ: {a, b}
  • Γ: {a, b, X, Y, B}
  • q₀: q0
  • B: Blank symbol 'B'
  • F: {q_acc}
Strategy & Transitions

The string is formed by exactly one extra 'a' at the beginning, followed by an equal number of a's and b's (e.g., aabb, aaabbb).
Step 1: Start at q0. Read the very first 'a', leave it as 'a' (or mark it), and move Right to q1. This skips the extra '+1' 'a'.
Step 2: At q1, mark the next 'a' as 'X' and move right to q2.
Step 3: At q2, scan right past any 'a's and 'Y's until a 'b' is found. Mark 'b' as 'Y' and move left to q3.
Step 4: At q3, scan left past 'Y's and 'a's until 'X' is found. Move right, return to q1.
Step 5: Repeat until q1 sees a 'Y' (meaning all 'a's are marked). Move to q4, verify only 'Y's remain until 'B' is hit, then go to q_acc.

Q3a
Closure Properties of Regular & CFG Languages
[10]
Prove the following languages are closed under operations union, concatenation, and Kleene closure: (i) Regular Language (ii) Context Free Language
(i) Proof for Regular Languages

Let L1 and L2 be two regular languages. By definition, there exist Regular Expressions R1 and R2 that denote L1 and L2 respectively.

  • Union: The regular expression (R1 + R2) generates all strings that belong to either L1 or L2. Since (R1 + R2) is a valid Regular Expression, the union L1 ∪ L2 is regular.
  • Concatenation: The regular expression (R1 • R2) generates strings formed by concatenating a string from L1 with a string from L2. Since it is a valid RE, the concatenation is regular.
  • Kleene Closure: The regular expression (R1)* generates zero or more concatenated strings from L1. This is a valid RE, thus the closure is regular.
(ii) Proof for Context-Free Languages

Let L1 and L2 be Context-Free Languages. Therefore, they have Context-Free Grammars G1 = (V1, T, P1, S1) and G2 = (V2, T, P2, S2). Assume V1 and V2 have disjoint non-terminals.

  • Union: Create a new grammar G with a new start symbol S. Add the production rule: S → S1 | S2. This grammar successfully generates L1 ∪ L2, proving union is a CFL.
  • Concatenation: Create a new grammar G with start symbol S. Add the production rule: S → S1 S2. This generates all concatenated strings, proving concat is a CFL.
  • Kleene Closure: Create a new grammar G with start symbol S. Add the production rule: S → S1 S | ε. This recursively generates L1*, proving Kleene closure is a CFL.

Turing Machine to Compare Two Unary Numbers
[10]
Design Turing Machine to Compare two numbers 'm' and 'n' represented in unary format and produce output: 'G' if m>n, 'S' if m<n, 'E' if m=n.
Formal Turing Machine (7-tuple)
  • Q: {q0, q1, q2, q3, q4, q_G, q_S, q_E}
  • Σ: {1, 0} (Input format: 1^m 0 1^n)
  • Γ: {1, 0, X, Y, B, G, S, E}
  • q₀: q0
  • B: Blank symbol
  • F: {q_G, q_S, q_E} (Halting/Output states)
Algorithm & Strategy

Input format is `111...0...111`. We ping-pong between the left number (m) and the right number (n).
1. Mark the first '1' of m as 'X'. Move right to cross '0'.
2. Find the first '1' of n, mark it as 'Y'. Scan left back to 'X', move one step right, repeat.
3. Evaluating Outcomes:
- If we search for a '1' in m but hit '0', then `m` is exhausted. We check `n`. If `n` has more '1's left, then `m < n` (Output 'S'). If `n` is also exhausted (only hits 'Y' or 'B'), then `m = n` (Output 'E').
- If we mark a '1' in m, scan right, but hit 'B' before finding a '1' in n, then `n` exhausted first, so `m > n` (Output 'G').

Pushdown Automata (Unequal 0s and 1s)
[10]
Construct pushdown automata for the following language: L = { w∈{0,1}* | n₀(w) ≠ n₁(w) }
Strategy

The PDA uses the stack to track the surplus of 0s or 1s.
- If the stack is empty (Z₀) or contains 0s, and we read a '0', we push it.
- If the stack is empty or contains 1s, and we read a '1', we push it.
- If the stack contains 0s and we read a '1', we pop (a match cancels out).
- If the stack contains 1s and we read a '0', we pop.
At the end of the input (reading ε), if the stack contains ANY 0s or 1s (top is not Z₀), we transition to the final state, meaning counts are unequal.

  • Σ: {0, 1}
  • Γ: {0, 1, Z₀}
  • q₀: q0
  • Z₀: Initial stack symbol
  • F: {q1} (Accept state)

Simplify Grammar
[5]
Simplify the following grammar:
S → a | Xb | aYa
X → Y | ε
Y → b | ε
Step 1: Eliminate ε-productions

Identify Nullable variables. Y → ε makes Y nullable. Since X → Y, X is also nullable (X → ε).

Substitute Y=ε and X=ε into RHS of all productions: Y → b X → Y | b | ε (Since Y is removed, X produces what Y produced + ε substitution) S → a | Xb | b | aYa | aa (Substituted X=ε giving 'b', Y=ε giving 'aa') Remove explicit ε rules: Y → b X → Y | b S → a | Xb | b | aYa | aa
Step 2: Eliminate Unit Productions

Identify Unit productions. We have X → Y. We substitute the RHS of Y (which is 'b') into X.

Y → b X → b | b => X → b S → a | Xb | b | aYa | aa
Step 3: Eliminate Useless Symbols

Can we reach all non-terminals from Start (S)? Yes, S generates `Xb` and `aYa`, so both X and Y are reachable. Do all non-terminals derive terminal strings? Yes, X → b and Y → b. Thus, there are no useless symbols.

Final Simplified Grammar: S → a | Xb | b | aYa | aa X → b Y → b

To convert a Mealy machine into a Moore machine, we must split states based on the diverse outputs of incoming edges.

Assume state S1 receives some incoming edges with output '0' and some with output '1'. Because a Moore machine state can only have ONE output, we must split S1 into two distinct states: S1_0 (which outputs 0) and S1_1 (which outputs 1).

Short Notes
[20]
Write short notes on Chomsky Hierarchy, Compare TM/PDA/FSM, PDA Tuples, Recursive vs RE.
a. Chomsky Hierarchy [5]

The Chomsky Hierarchy classifies formal grammars into 4 strictly inclusive nested levels:

  • Type 3 (Regular): Strictest rules. Productions like A → aB or A → a. Accepted by Finite Automata.
  • Type 2 (Context-Free): Rules like A → γ (LHS is exactly one non-terminal, RHS is any string). Accepted by Pushdown Automata.
  • Type 1 (Context-Sensitive): Rules like αAβ → αγβ (|LHS| ≤ |RHS|). The context (α, β) around A matters. Accepted by Linear Bounded Automata.
  • Type 0 (Unrestricted): No restrictions. α → β. Accepted by Turing Machines.

c. PDA Tuples & Elements [5]

A Pushdown Automaton is a 7-tuple M = (Q, Σ, Γ, δ, q₀, Z₀, F) where Q=states, Σ=input alphabet, Γ=stack alphabet, δ=transition function, q₀=start state, Z₀=initial stack symbol, F=final states.

Its core physical elements include:

  • Input Tape: Divided into cells, read-only, moving strictly left-to-right.
  • Finite Control: The CPU/states governing transition decisions.
  • Stack: Infinite memory following Last-In-First-Out (LIFO). Can only read/pop the top element.
d. Recursive vs Recursively Enumerable [5]
  • Recursive (Decidable): A language L is recursive if there exists a TM that halts on every input. If w ∈ L, it halts and accepts. If w ∉ L, it explicitly halts and rejects. It never loops infinitely.
  • Recursively Enumerable (RE / Partially Decidable): A language L is RE if there exists a TM that will halt and accept if w ∈ L. However, if w ∉ L, the TM might reject, OR it might loop forever. We cannot guarantee termination for rejected strings.
