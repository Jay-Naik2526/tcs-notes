Q1a
Ambiguous Grammar & Testing
[5]
What is ambiguous grammar? Test the following grammar G for ambiguity, and if G is ambiguous, what is the cause of ambiguity?
G = {E, (+,*,a), {E → E+E, E → E*E, E → a}, E}
Answer

Ambiguous Grammar: A Context-Free Grammar (CFG) is ambiguous if there exists at least one string in its language that can be generated by more than one leftmost derivation (or equivalently, has more than one distinct parse tree).

Testing for Ambiguity: Let's test the string w = a + a * a

Parse Tree 1 (Leftmost derivation prioritizing +): E ⇒ E + E ⇒ a + E ⇒ a + E * E ⇒ a + a * E ⇒ a + a * a Parse Tree 2 (Leftmost derivation prioritizing *): E ⇒ E * E ⇒ E + E * E ⇒ a + E * E ⇒ a + a * E ⇒ a + a * a

Since the string a + a * a has two distinct leftmost derivations (and two distinct parse trees), the grammar G is ambiguous.

Cause of Ambiguity: The grammar lacks precedence and associativity rules. Both '+' and '*' are at the same hierarchical level, allowing the parser to arbitrarily choose which operation to bind first.

Q1b
Design PDA for CFG
[5]
Design pushdown automata for the following context-free grammar: S → SS | (S) | ()
Answer

To construct a PDA from a CFG, we use top-down parsing (simulating leftmost derivation on the stack). We push the start symbol 'S' and replace non-terminals with their productions.

PDA M = (Q, Σ, Γ, δ, q0, Z, F) where Q={q0, q1, q_acc}, Σ={(, )}, Γ={S, (, ), Z}

δ(q0, ε, Z) = {(q1, SZ)} // Push start symbol // CFG Production Transitions (replace NT with RHS) δ(q1, ε, S) = {(q1, SS), (q1, (S)), (q1, ())} // Terminal Match Transitions (pop matching terminals) δ(q1, '(', '(') = {(q1, ε)} δ(q1, ')', ')') = {(q1, ε)} // Acceptance on empty stack δ(q1, ε, Z) = {(q_acc, Z)}
Q1c
Turing Machine vs Mealy Machine
[5]
Give Formal Definition of Turing Machine & Mealy Machine. How they are different from each other.
Formal Definitions

Turing Machine (7-tuple): M = (Q, Σ, Γ, δ, q₀, B, F)
Q: States, Σ: Input Alphabet, Γ: Tape Alphabet, δ: Transition function (Q × Γ → Q × Γ × {L, R}), q₀: Start state, B: Blank symbol, F: Final states.

Mealy Machine (6-tuple): M = (Q, Σ, Δ, δ, λ, q₀)
Q: States, Σ: Input Alphabet, Δ: Output Alphabet, δ: Transition function (Q × Σ → Q), λ: Output function (Q × Σ → Δ), q₀: Start state.

Q1d
Applications of RE and Grammar
[5]
What are the applications of Regular Expression and Grammar in Compiler Constructions? Explain.
Answer

1. Regular Expressions (Lexical Analysis):
In the first phase of compilation (Lexical Analysis or Scanning), Regular Expressions are used to specify the patterns of valid tokens. For example, identifiers `[a-zA-Z][a-zA-Z0-9]*` or integers `[0-9]+`. The compiler builds a DFA from these REs to efficiently read the source code stream and group characters into meaningful tokens. Tools like Lex/Flex use REs to generate lexical analyzers.

2. Grammars (Syntax Analysis):
In the second phase (Syntax Analysis or Parsing), Context-Free Grammars (CFG) are used to define the hierarchical structure (syntax) of the programming language. For example, `Stmt → if (Expr) Stmt else Stmt`. The compiler uses PDA-based parsing algorithms (like LL or LR parsers) to verify that the sequence of tokens forms a valid syntax tree. Tools like Yacc/Bison use CFGs to automatically generate parsers.

Q2a
DFA vs NFA & DFA Construction
[10]
How is DFA different from NFA? Construct DFA, which accepts all strings ending with 00 or 11 over Σ={0,1}.
DFA vs NFA

DFA (Deterministic): For every state and input symbol, there is exactly ONE transition. No ε-transitions. Every input path is uniquely determined.
NFA (Non-Deterministic): From a state, an input symbol can lead to ZERO, ONE, or MULTIPLE next states. Can include ε-transitions (moving without input). Guesses the correct path to acceptance.

DFA Construction (Ends in 00 or 11)

States track the last two symbols seen: start (ε), seen '0', seen '1', seen '00' (accept), seen '11' (accept).

Q2b
Turing Machine for a^(n+1) b^n
[10]
Construct & verify Turing machine to recognize the language L={aⁿ⁺¹bⁿ | n≥1}
Strategy

The string is formed by exactly one extra 'a' at the beginning, followed by equal a's and b's. (e.g. aabb, aaabbb).
Step 1: Read the very first 'a', move Right (skipping it permanently).
Step 2: Now match remaining a's with b's (standard aⁿbⁿ logic: mark 'a' as X, scan right to mark 'b' as Y, scan left to X, repeat).
Step 3: If only Y's remain, Accept.

Q3a
Closure Properties of Regular & CFG Languages
[10]
Prove the following languages are closed under operations union, concatenation, and Kleene closure: (i) Regular Language (ii) Context Free Language
(i) Regular Languages

If L1 and L2 are regular, they can be represented by Regular Expressions R1 and R2.

  • Union: The regular expression (R1 + R2) represents L1 ∪ L2. Since (R1 + R2) is a valid RE, the union is regular.
  • Concatenation: The regular expression (R1 • R2) represents L1 concatenated with L2. Since (R1R2) is a valid RE, concat is regular.
  • Kleene Closure: The expression (R1)* represents the Kleene closure of L1. Since it's a valid RE, it's regular.
(ii) Context-Free Languages

If L1 and L2 are CFLs, they have Context-Free Grammars G1 (start S1) and G2 (start S2) with disjoint non-terminals.

  • Union: Create a new grammar G with start symbol S. Add rule: S → S1 | S2. This generates either a string from G1 or G2. Therefore, Union is CFL.
  • Concatenation: Create a new grammar G. Add rule: S → S1 S2. This generates a string from G1 followed by G2. Therefore, Concat is CFL.
  • Kleene Closure: Create a new grammar G for L1*. Add rule: S → S1 S | ε. This generates zero or more instances of strings from G1. Therefore, Kleene Closure is CFL.

Q4b
Turing Machine to Compare Two Unary Numbers
[10]
Design Turing Machine to Compare two numbers 'm' and 'n' in unary format and output 'G' (m>n), 'S' (m<n), or 'E' (m=n).
Strategy (Input: 1^m 0 1^n)

We ping-pong between the left number (m) and the right number (n).
1. Find the first '1' of m, replace with X.
2. Scan right past the '0' to find the first '1' of n, replace with Y.
3. Scan back left to X, move one step right, repeat.
Outcomes:
- If we look for a '1' in m but hit '0' -> m is exhausted. Check if n is also exhausted. If n has more '1's -> Output 'S'. If n is exhausted -> Output 'E'.
- If we mark a '1' in m, scan right, but hit 'B' before finding a '1' in n -> n is exhausted first -> Output 'G'.

δ(q0, 1) = (q1, X, R) [Mark m's 1] δ(q1, 1) = (q1, 1, R) [Scan right] δ(q1, 0) = (q2, 0, R) [Cross boundary] δ(q2, Y) = (q2, Y, R) [Skip matched n's] δ(q2, 1) = (q3, Y, L) [Mark n's 1, head back] δ(q3, Y/0/1) = (q3, Y/0/1, L) [Scan left] δ(q3, X) = (q0, X, R) [Found X, loop] // Base conditions: δ(q0, 0) = (q4, 0, R) [m is empty. Check n] δ(q4, Y) = (q4, Y, R) δ(q4, B) = (q_E, E, N) [Both empty = EQUAL] δ(q4, 1) = (q_S, S, N) [n has extra = SMALLER] δ(q2, B) = (q_G, G, N) [m had 1, but n is empty = GREATER]
Q5a
Pushdown Automata (Unequal 0s and 1s)
[10]
Construct PDA for L = { w∈{0,1}* | n_0(w) ≠ n_1(w) }
Strategy

The PDA uses the stack to track the "surplus" of 0s or 1s.
- If stack has Z₀ (empty) or 0s: Push on reading '0'.
- If stack has Z₀ (empty) or 1s: Push on reading '1'.
- If stack has 0s and we read '1': Pop.
- If stack has 1s and we read '0': Pop.
At the end of the string, if the stack contains ANY 0s or 1s (i.e., top is not Z₀), we accept using an ε-transition to the final state.

M = ( {q0, q1}, {0,1}, {0, 1, Z0}, δ, q0, Z0, {q1} ) // Push surplus δ(q0, 0, Z0) = {(q0, 0Z0)} δ(q0, 1, Z0) = {(q0, 1Z0)} δ(q0, 0, 0) = {(q0, 00)} δ(q0, 1, 1) = {(q0, 11)} // Pop matches δ(q0, 1, 0) = {(q0, ε)} δ(q0, 0, 1) = {(q0, ε)} // Accept if stack has surplus 0s or 1s at end of string δ(q0, ε, 0) = {(q1, 0)} [Accept] δ(q0, ε, 1) = {(q1, 1)} [Accept]

Simplify: S → a | Xb | aYa ; X → Y | ε ; Y → b | ε
Step 1: Eliminate ε-productions

Nullable variables: Y → ε. Since X → Y, X is also nullable (X → ε).

Substitute Y=ε and X=ε in RHS: Y → b X → Y | b | ε (since Y->b) => X → Y (remove e) S → a | Xb | b | aYa | aa
Step 2: Eliminate Unit Productions

Unit productions: X → Y. Substitute RHS of Y into X.

Y → b X → b S → a | Xb | b | aYa | aa
Step 3: Eliminate Useless Symbols

Can we reach all variables from S?
S produces 'Xb' and 'aYa', so X and Y are reachable. Both produce terminals. No useless symbols.

Final Simplified Grammar: S → a | Xb | b | aYa | aa X → b Y → b

Moore vs Mealy Machine & Conversion
[5]
Differentiate between Moore and Mealy Machines. Construct the Moore machine for the given Mealy machine. (Diagram references: a/0, b/0, a/1, b/1, S0, S1)
Moore vs Mealy
Moore MachineMealy Machine
Output depends ONLY on the current state.Output depends on current state AND input symbol.
Output is associated with the state (placed inside the state circle).Output is associated with the transition (placed on the edges).
More states usually required to represent the same logic.Fewer states usually required.
Reacts slower to input changes (output changes after transition).Reacts faster (output changes during transition).
Conversion from Mealy to Moore

Given a Mealy machine with states S0 and S1 and inputs a/b producing outputs 0/1. To convert to a Moore machine, we must split states based on the incoming outputs.

Assume S1 receives an edge with output '0' and an edge with output '1'. We split S1 into two states: S1_0 (which outputs 0) and S1_1 (which outputs 1). All incoming edges that had output '0' will now go to S1_0. All incoming edges that had output '1' will go to S1_1. Outgoing edges from S1_0 and S1_1 remain identical to the original S1.

Example Transformation Steps: 1. Identify all incoming transition outputs for each state. 2. If state S_i receives inputs with outputs x and y, split S_i into S_ix and S_iy. 3. Assign the Moore output: Output(S_ix) = x, Output(S_iy) = y. 4. Route incoming edges to the respective new states based on the edge's original output. 5. Duplicate outgoing edges from the original S_i to all new split states.
Q6
Short Notes
[20]
Write short notes on Chomsky Hierarchy, Compare TM/PDA/FSM, PDA Tuples, Recursive vs RE.
a. Chomsky Hierarchy [5]

Classifies grammars into 4 types:
Type 3 (Regular): A → aB or A → a. Accepted by FA.
Type 2 (Context-Free): A → γ (RHS can be anything). Accepted by PDA.
Type 1 (Context-Sensitive): αAβ → αγβ (|LHS| ≤ |RHS|). Accepted by LBA.
Type 0 (Unrestricted): α → β. Accepted by Turing Machine.

b. Compare TM, PDA, FSM [5]
MachineMemoryPowerLanguage
FSMNone (Only states)WeakestRegular
PDALIFO Stack (Infinite length)MediumContext-Free
TMInfinite Tape (R/W, 2-way)Highest (General CPU)Recursively Enumerable
c. PDA Tuples & Elements [5]

A PDA is a 7-tuple M = (Q, Σ, Γ, δ, q₀, Z₀, F).
Elements: Input Tape (one-way read-only), Finite Control (states), and Stack (infinite capacity, LIFO access, initialized with Z₀).

d. Recursive vs Recursively Enumerable [5]

Recursive (Decidable): A language L is recursive if there exists a TM that halts on every input. It accepts if w∈L, and explicitly REJECTS (halts) if w∉L.
Recursively Enumerable (RE / Partially Decidable): A language L is RE if there exists a TM that halts and accepts if w∈L. If w∉L, the TM might reject OR loop forever.
