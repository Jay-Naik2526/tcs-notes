Q1a
Formal Language and Finite Automata
[5]
What do you understand by formal language and finite automata? Explain
Formal Language

A Formal Language is a set of strings of symbols constrained by rules (a grammar). It consists of an alphabet Σ (set of symbols) and a set of valid words formed from these symbols. Examples include regular languages, context-free languages, and recursively enumerable languages. Unlike natural languages, formal languages have strict mathematical definitions, making them suitable for parsing by machines.

Finite Automata

A Finite Automata (FA) is the simplest computational model (or abstract machine) used to recognize patterns and accept regular languages. It has a finite number of states, reads input symbols one by one, and transitions between states. It lacks external memory (like a stack or tape), meaning it can only remember its current state. FAs are widely used in lexical analysis, text searching, and protocol design.

Q1b
Regular Expressions to English Statements
[5]
Define Regular Expression and convert the following into equivalent English statements:
R1 = b*ab*ab*
R2 = (a+b)*(aa+bb)(a+b)*
R3 = a(a+b)*a
Definition

A Regular Expression (RE) is an algebraic formula that describes a regular language using operations like union (+), concatenation (·), and Kleene closure (*). It serves as a declarative way to specify patterns that a Finite Automaton can recognize.

Conversions
  • R1 = b*ab*ab*: The set of all strings over {a, b} that contain exactly two 'a's.
  • R2 = (a+b)*(aa+bb)(a+b)*: The set of all strings over {a, b} that contain either 'aa' or 'bb' as a substring (i.e., at least two consecutive identical symbols).
  • R3 = a(a+b)*a: The set of all strings over {a, b} that start and end with the symbol 'a', with a length of at least 2.

Q1d
Turing Machine as Finite Control
[5]
Explain Turing Machine as finite control and tuples of the Turing machine with suitable example.
Turing Machine Control

A Turing Machine (TM) consists of a finite control (a state machine), an infinite read/write tape divided into cells, and a moving tape head. The finite control dictates the machine's actions based on its current state and the symbol the head is currently reading. The machine can overwrite the symbol, change its state, and move the head one step left (L) or right (R).

7-Tuple Definition M = (Q, Σ, Γ, δ, q0, B, F)
  • Q: Finite set of states (e.g., {q0, q1, qacc})
  • Σ: Input alphabet (e.g., {0, 1})
  • Γ: Tape alphabet, where Σ ⊂ Γ (e.g., {0, 1, X, Y, B})
  • δ: Transition function Q × Γ → Q × Γ × {L, R}
  • q0: Start state (q0 ∈ Q)
  • B: Blank symbol (B ∈ Γ, B ∉ Σ)
  • F: Set of final/accepting states (F ⊆ Q)

Q4b
Universal Turing Machine & Halting Problem
[10]
Write a short note on: i. Universal Turing machine, ii. Halting problem
Universal Turing Machine (UTM)

A UTM is a Turing Machine capable of simulating any other Turing Machine. It takes as input the encoded description of a TM M and an input string w. The UTM then simulates the execution of M on w. This proves that software is conceptually equivalent to hardware, forming the basis of modern stored-program computers.

Halting Problem

The Halting Problem asks whether it is possible to write a general program (or TM) that can determine, for any given program M and input w, if M will eventually halt (finish) or run forever in an infinite loop. Alan Turing proved this is undecidable. No such general algorithm exists, which places a fundamental limit on what computers can compute or verify.

Q5a
Greibach Normal Form (GNF)
[10]
Discuss GNF and convert: S→AB|A, A→aA|ε, B→bB|ε
Greibach Normal Form

A CFG is in GNF if all productions are of the form A → aα, where a is a single terminal and α is a string of zero or more non-terminals. It is useful for proving properties of CFLs and constructing PDAs.

Conversion Steps
1. Remove ε-productions: Nullable = {A, B, S}. New productions: A → aA | a B → bB | b S → AB | A | B | aA | bB | a | b 2. Convert to GNF (substitute to ensure first symbol is terminal): S → aAB | aB | bB | b | aA | a | b A → aA | a B → bB | b The grammar is now in GNF since every RHS starts with exactly one terminal.

Q6b
Limitations of Finite State Machine
[5]
State and explain the limitations of the finite state machine (FSM).
Limitations
  • No Auxiliary Memory: An FSM relies entirely on its current state to "remember" past inputs. It does not have an external stack or tape.
  • Cannot Count Arbitrarily: Because the number of states is finite, an FSM cannot count an unbounded sequence. It cannot verify if two arbitrarily large sequences have the same length.
  • Cannot Recognize Context-Free Languages: FSMs cannot process strings with nested dependencies, such as matching parentheses or languages like L = {aⁿbⁿ | n ≥ 0}.
  • No Complex Arithmetic: Multiplication or division of arbitrarily large numbers cannot be computed purely with an FSM.

Q7a
Pumping Lemma & L = a^2n
[10]
State pumping lemma for regular language and prove L={a²ⁿ | n≥1} is regular.
Pumping Lemma Statement

If L is regular, there exists an integer p ≥ 1 such that any string w in L with |w| ≥ p can be divided into three parts, w = xyz, such that: |y| > 0, |xy| ≤ p, and for all i ≥ 0, xyⁱz is also in L.

Proof L is Regular

L = {a², a⁴, a⁶, ...} consists of strings of 'a's with even length ≥ 2. This can be expressed by the Regular Expression aa(aa)*. Because a regular expression can be written for it, the language is fundamentally regular. It can be easily accepted by a 2-state DFA. Thus, it automatically satisfies the Pumping Lemma conditions (e.g., choose p=2, y=aa).

Q7b
Compiler Lexical Analysis
[5]
How is TCS applicable in the implementation of a lexical analyzer? What are the steps?
Lexical Analyzer (TCS Application)

A lexical analyzer scans source code and groups characters into meaningful tokens (keywords, identifiers, numbers). Theoretical Computer Science applies here because token patterns are defined using Regular Expressions, and the analyzer engine is implemented as a Deterministic Finite Automaton (DFA).

Steps followed by lexical analyzer: 1. Read the input stream of characters. 2. Apply Regular Expressions (converted to NFAs, then minimized DFAs internally). 3. Identify the longest matching prefix for a token. 4. Emit the token and value to the parser. 5. Discard whitespaces and comments.
Q7c
Power of PDA
[5]
Explain the power of PDA over FSM.
Power of PDA over FSM

A Pushdown Automaton (PDA) is strictly more powerful than a Finite State Machine (FSM). While an FSM has severely limited memory (only its current state), a PDA includes an infinite stack. This stack allows a PDA to count and match nested structures (like checking if n 'a's match n 'b's in aⁿbⁿ), which an FSM fundamentally cannot do. FSMs recognize Regular Languages, while PDAs recognize the larger class of Context-Free Languages.
