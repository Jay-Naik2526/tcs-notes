1.1 What is Theoretical Computer Science (TCS)?
Definition

Theoretical Computer Science (TCS) — also called Theoretical Computer Science or Automata Theory — is defined as: "Mathematically modeling a machine and doing the theoretical study of that machine."

TCS is a subset of Computer Science and Mathematics. It focuses on abstract aspects of computing rather than physical implementation.

Three Major Branches of TCS
Branch What It Studies
Automata Theory & Languages Abstract machines (automata) and the problems they solve. Types: Finite Automaton (FA), Pushdown Automaton (PDA), Turing Machine (TM).
Computability Theory What CAN and CANNOT be computed by machines (Recursion Theory).
Computational Complexity Theory How EFFICIENTLY problems can be solved — in terms of time and space resources.
Why Study TCS? (Real Applications)
# Application TCS Concept Used
1 Compiler Construction FA for tokens, CFG for syntax
2 Search Engines Finite automata for pattern matching and indexing
3 Communication Protocols FA models protocols and electronic circuits
4 Natural Language Processing (NLP) Automata models for language analysis
5 Undecidable Problems TCS proves that no program can ever solve certain problems
6 Intractable Problems Programs exist but are too slow (NP-Hard, NP-Complete)
Simple Example

A light switch can be either ON or OFF. We can model this as a finite automaton with 2 states. Pressing the switch changes the state. This is the most basic example of a finite automaton modeling a real-world machine.

1.2 Basic Concepts: Symbols, Alphabets & Strings

These are the foundational building blocks of formal language theory. Everything in TCS is built from these primitives.

1.2.1 Symbols
Definition

Symbols are the smallest building blocks — atomic units. They are individual characters that cannot be broken down further.

Examples of Symbols

English letters: a, b, c, ..., z

Digits: 0, 1, 2, ..., 9

Special characters: $, #, @, &

Notation: If a is in set V → write a ∈ V. If not → write b ∉ V.

1.2.2 Alphabets (Σ)
Definition

An alphabet is a finite, non-empty set of symbols. Denoted by Σ (Sigma). Empty set ∅ is NOT a valid alphabet.

Alphabet (Σ) Description
{0, 1} Binary alphabet — most common in TCS
{0, 1, 2, ..., 7} Octal digit set
{a, b, c, ..., z} English lowercase letters
{a, b} Simple two-symbol alphabet (used in most examples)
1.2.3 Strings / Words
Definition

A string is a finite sequence of symbols chosen from an alphabet Σ. Denoted by lowercase letters: w, x, y, z.

Examples

w = 1001 over Σ = {0, 1}

w = abba over Σ = {a, b}

w = aaabcabcb over Σ = {a, b, c}

Length of a String — |w|
Definition

The length of a string is the total count of symbols in it. Denoted by |w|.

Example — w = "aaabcabcb"

|w| = 9 → total length

|w|ₐ = 4 → count of 'a' symbols

|w|_b = 3 → count of 'b' symbols

|w|_c = 2 → count of 'c' symbols

Check: 4 + 3 + 2 = 9 ✓

1.2.4 Empty String (ε)
Definition

The empty string (also called null string) is a string with zero occurrences of symbols. Denoted by ε (epsilon) or ϵ.

Key Properties of ε
  • |ε| = 0 — length is zero
  • ε is a valid string over ANY alphabet
  • Concatenation: w · ε = ε · w = w (identity element)
  • ε ∈ Σ* always (for any Σ)
  • ε ∉ Σ⁺ (not in positive closure)
1.2.5 Prefix, Suffix, and Substring

For a string w = "abc":

Term Definition Examples for w = "abc"
Prefix Remove zero or more trailing symbols from w ε, a, ab, abc
Suffix Remove zero or more leading symbols from w ε, c, bc, abc
Substring Remove a prefix AND a suffix from w ε, a, b, c, ab, bc, abc
Important Relationship
  • Every prefix is a substring. Every suffix is a substring.
  • NOT every substring is a prefix or suffix (e.g., "b" in "abc" is a substring but neither prefix nor suffix).
  • For w of length n: number of prefixes = n+1, suffixes = n+1, substrings ≤ n(n+1)/2 + 1.
1.2.6 Powers of an Alphabet (Σᵏ)
Definition

Σᵏ is the set of ALL strings of exactly length k that can be formed from Σ.

For Σ = {a, b}:

Power Meaning Set of Strings Count
Σ⁰ Strings of length 0 {ε} 1
Σ¹ Strings of length 1 {a, b} 2
Σ² Strings of length 2 {aa, ab, ba, bb} 4
Σ³ Strings of length 3 {aaa, aab, aba, abb, baa, bab, bba, bbb} 8
Σⁿ Strings of length n All n-length strings 2ⁿ
|Σᵏ| = |Σ|ᵏ   (for alphabet of size |Σ|)
1.2.7 Kleene Closure (Σ*) and Positive Closure (Σ⁺)
Kleene Closure — Σ*

Σ* is the set of ALL possible strings (including ε) that can be formed from Σ.

Σ* = Σ⁰ ∪ Σ¹ ∪ Σ² ∪ Σ³ ∪ ...   (infinite set)
Example — Σ = {a, b}

Σ* = {ε, a, b, aa, ab, ba, bb, aaa, aab, aba, abb, baa, bab, bba, bbb, ...}

Positive Closure — Σ⁺

Σ⁺ is the set of ALL non-empty strings formed from Σ. ε is EXCLUDED.

Σ⁺ = Σ¹ ∪ Σ² ∪ Σ³ ∪ ... = Σ* − {ε}
Example — Σ = {a, b}

Σ⁺ = {a, b, aa, ab, ba, bb, aaa, aab, aba, abb, ...}

Property Σ* Σ⁺
Includes ε? ✅ Yes ❌ No
Finite or Infinite? Infinite Infinite
Relation Σ* = Σ⁺ ∪ {ε} Σ⁺ = Σ* − {ε}
Starts from Σ⁰ (length 0) Σ¹ (length 1)
Common Exam Trap

If Σ = ∅ (empty alphabet), then Σ* = {ε} and Σ⁺ = ∅. An empty alphabet is NOT allowed in practice, but this is a common trick question.

1.3 Formal Language
Definition

A formal language L over alphabet Σ is any subset of Σ*. That is: L ⊆ Σ*. A language is simply a SET of strings that follow specific rules.

Important Points
  • Σ* itself is a language (the universal language over Σ).
  • {ε} is a valid language (contains only empty string).
  • ∅ (empty set) is a valid language (the empty language — no strings accepted).
  • Note: {ε} ≠ ∅ — do not confuse them!
Language Description
L = {0, 1, 00, 11, 01, 10, ...} All binary strings (= Σ* for Σ={0,1})
L = {0ⁿ1ⁿ | n ≥ 0} n zeros followed by n ones: ε, 01, 0011, 000111, ...
L = {w ∈ {a,b}* | |w| is even} All even-length strings over {a,b}
L = {w ∈ {a,b}* | #a is divisible by 2} Strings where count of 'a' is even
L = {w ∈ {a,b}* | #b is divisible by 3} Strings where count of 'b' is multiple of 3
L = ∅ Empty language — accepts nothing
1.3.1 Operations on Languages

Since languages are sets, all standard set operations apply:

Operation Notation Meaning Example
Union L₁ ∪ L₂ Strings in L₁ OR L₂ {a} ∪ {b} = {a,b}
Intersection L₁ ∩ L₂ Strings in BOTH L₁ AND L₂ {a,b} ∩ {b,c} = {b}
Difference L₁ − L₂ Strings in L₁ but NOT in L₂ {a,b} − {b} = {a}
Complement L̄ or L' All strings in Σ* that are NOT in L L̄ = Σ* − L
Concatenation L₁ · L₂ {xy | x ∈ L₁, y ∈ L₂} {a}{b} = {ab}
Kleene Closure L* Zero or more concatenations of L {a}* = {ε,a,aa,aaa,...}
Positive Closure L⁺ One or more concatenations of L {a}⁺ = {a,aa,aaa,...}
1.3.2 Language Defined by Grammar

A formal language is defined by a grammar — a set of production rules. The language L(G) is the set of all strings derivable from the start symbol.

Example — Grammar G for "all strings over {a, b} without ε"
S → aS | bS | a | b

This generates: L(G) = {a, b, aa, ab, ba, bb, aaa, aab, ...} = Σ⁺ for Σ = {a,b}

1.4 Basic Set Theory Concepts

These are the mathematical foundations needed to understand languages and automata.

Methods of Set Representation
  • Listing: E = {0, 2, 4, ..., 50}
  • Set Builder: V = {x | x is a vowel}
  • Recursion: A = {x | x = n², x < 100}
Subset & Power Set
  • A ⊆ B → every element of A is in B
  • ∅ ⊆ every set; every set ⊆ itself
  • Power set P(A): all subsets of A
  • |P(A)| = 2ⁿ (n = |A|)
Set Operations
  • A ∪ B — elements in A or B
  • A ∩ B — elements in both
  • A − B — in A but not B
  • Ā = U − A — complement
Cartesian Product

A × B = {(a,b) | a ∈ A and b ∈ B}

Example: {1,2} × {x,y} = {(1,x),(1,y),(2,x),(2,y)}

|A × B| = |A| × |B|

Power Set Example

For A = {0, 1, 2}, |A| = 3 → |P(A)| = 2³ = 8

P(A) = {∅, {0}, {1}, {2}, {0,1}, {0,2}, {1,2}, {0,1,2}}

1.5 Grammar (Formal Definition)
Definition

A grammar G is a set of production rules used to generate strings of a language. It is formally defined as a 4-tuple: G = (V, T, P, S)

Symbol Name Description Example
V Variables / Non-Terminals Symbols that can be replaced by production rules S, A, B
T Terminals Actual symbols of the language (cannot be replaced) a, b, 0, 1
P Productions Rules of the form α → β (replace α with β) S → aS | b
S Start Symbol The starting variable; S ∈ V S
Example — Grammar for (a+b)*abb

G = (V, T, P, S) where V = {S, A}, T = {a, b}, S = S

S → Aabb
A → aA | bA | ε

This generates: abb, aabb, babb, aaabb, ababb, ...

Note — V ∩ T = ∅
  • Non-terminals and terminals must be disjoint sets — a symbol is either a variable OR a terminal, never both.
  • Strings derived from S that contain ONLY terminals form the language L(G).
  • A string in derivation that contains at least one non-terminal is called a sentential form.
1.6 Chomsky Hierarchy

In 1957, Noam Chomsky classified formal grammars into four types in his work "Syntactic Structures". This classification is called the Chomsky Hierarchy.

Notation used in production rules
  • A, B — Non-terminals (single variables)
  • a, b — Terminals (single symbols)
  • α, β, γ — Sentential forms (strings of terminals and/or non-terminals)
  • ε — Empty string

Type 1 — Context Sensitive Grammar (CSG)
Type 1
Context Sensitive Grammar
Context Sensitive Language (CSL)
AutomatonLinear Bounded Automaton (LBA)
Production Formα₁Aα₂ → α₁βα₂   (β ≠ ε)
Constraint|RHS| ≥ |LHS| (non-contracting)
ExceptionS → ε allowed if S not in any RHS
Why "Context Sensitive"?
  • Variable A can be replaced by β ONLY when it appears in the context of α₁ on the left and α₂ on the right.
  • The replacement depends on the surrounding symbols — hence "context sensitive".
  • Length of RHS ≥ Length of LHS — the grammar never contracts (except S → ε).
Type 1 Example
A → AB  |  AB → AC  |  AC → ab

Classic CSL example: L = {aⁿbⁿcⁿ | n ≥ 1} — equal numbers of a, b, c.

Type 2 — Context Free Grammar (CFG)
Type 2
Context Free Grammar
Context Free Language (CFL)
AutomatonPushdown Automaton (PDA)
Production FormA → α   (single non-terminal on LHS)
Context needed?NO — LHS is always a single variable
Used in?Syntax of programming languages, parsers
Why "Context Free"?
  • LHS of every production is a single non-terminal.
  • A can be replaced by α regardless of what surrounds it — no context needed.
  • CFGs are used to define the syntax of programming languages (C, Java, Python).
  • Parsers in compilers (LL, LR) are implementations of PDAs.
Type 2 Example — Palindromes over {a,b}
S → aSa | bSb | a | b | ε

Generates: ε, a, b, aa, bb, aba, bab, aaa, aba, bbb, abba, baab, ...

All strings w such that w = reverse(w).

1.6.5 Summary Table — Chomsky Hierarchy
Type Grammar Name Language Automaton Production Form
Type 0 Unrestricted Recursively Enumerable Turing Machine (TM) α → β (α ≠ ε)
Type 1 Context Sensitive Context Sensitive Linear Bounded Automaton (LBA) α₁Aα₂ → α₁βα₂ (β ≠ ε)
Type 2 Context Free Context Free (CFL) Pushdown Automaton (PDA) A → α
Type 3 Regular Regular Language Finite Automaton (DFA/NFA) A → aB | a (Right) or A → Ba | a (Left)
Hierarchy (Subset Relationship)
Regular ⊂ Context Free ⊂ Context Sensitive ⊂ Recursively Enumerable

Every Regular Language is a CFL. Every CFL is a CSL. Every CSL is Recursively Enumerable.

Figure: Chomsky Hierarchy — each type is a proper subset of the outer one
1.6.6 Other Grammar Classifications
By Derivation Trees
  • Ambiguous Grammar: At least one string has 2 or more different derivation (parse) trees.
  • Unambiguous Grammar: Every string has exactly ONE parse tree.
By Language Size
  • Finite Language: The language has a finite number of strings.
  • Infinite Language: The language has infinitely many strings (most languages in TCS).
1.7 Derivation Tree (Parse Tree)
Definition

A derivation tree (parse tree) is a graphical representation of how a string is derived from the start symbol S using the production rules of a grammar. It shows the hierarchical structure of a derivation.

Properties of a Derivation Tree
  • The root is always the Start Symbol (S).
  • Leaf nodes are terminals or ε.
  • Internal nodes are non-terminals.
  • If an internal node is labeled A and its children (left to right) are X₁, X₂, ..., Xₙ, then A → X₁X₂...Xₙ must be a production in G.
  • Reading leaf nodes from left to right gives the derived string (yield).
Example 1 — Deriving "aab" from S → aS | bS | a | b
        S
      /    \
     a     S
         /    \
        a     S
              |
              b

Derivation: S → aS → aaS → aab

Yield (read leaves left to right): a a b ✓

Example 2 — Deriving "abba" from S → aSa | bSb | a | b | ε (Palindromes)
           S
        /    |    \
       a    S     a
          /  |  \
         b  S   b
             |
             ε

Derivation: S → aSa → abSba → ab(ε)ba → abba

Ambiguity via Derivation Trees

If a string can be derived using two or more different derivation trees, the grammar is ambiguous. Ambiguity is a property of the grammar, not the language.

1.8 Application of TCS in Compiler Construction

Every phase of a compiler uses a concept from TCS. This is one of the primary motivations for studying Automata Theory.

Compiler Phase TCS Concept Used Purpose
Lexical Analysis Regular Expressions, DFA/NFA Token recognition — identifies keywords, identifiers, operators, literals
Syntax Analysis (Parsing) CFG, PDA Checks if the token sequence follows the grammar rules of the language
Semantic Analysis Attribute Grammars, Type Systems Type checking, scope analysis, semantic correctness
Code Generation & Optimization Turing Machines, Computability Understanding computational limits; what can and cannot be optimized
Lexical Analysis — How FA is Used

Consider the source code: int x = 5 + 3;

The lexer uses a DFA to scan and recognize tokens:

int → keyword token
x → identifier token
= → assignment operator token
5 → integer literal token
+ → plus operator token
3 → integer literal token
; → semicolon token

Each token type is described by a Regular Expression, which is converted to a DFA for efficient scanning.

Syntax Analysis — How CFG/PDA is Used

A simplified CFG for assignment statement:

stmt → id = expr ;
expr → expr + term | term
term → id | num

The parser (LL/LR) uses this CFG to build a parse tree and verify syntactic correctness.

1.9 Language — Grammar — Automata Connection

This is the heart of TCS. Each language class has a corresponding grammar (generator) and an automaton (recognizer) that are all equivalent in power.

Language Class Described By Accepted By (Recognizer) Generated By
Regular Language Regular Expression (RE) DFA, NFA, ε-NFA, Mealy, Moore Regular Grammar (Type 3)
Context Free Language CFG (Type 2) Pushdown Automaton (PDA) Context Free Grammar
Context Sensitive Language CSG (Type 1) Linear Bounded Automaton (LBA) Context Sensitive Grammar
Recursively Enumerable Unrestricted Grammar (Type 0) Turing Machine (TM) Unrestricted Grammar
Key Equivalences (Must Know for Exams)
  • RE = DFA = NFA = ε-NFA = Regular Grammar — all describe Regular Languages.
  • CFG = PDA — CFGs and PDAs are equivalent in power.
  • Every DFA is an NFA. Every NFA can be converted to a DFA (subset construction).
  • Not every CFL is regular. E.g., {0ⁿ1ⁿ | n ≥ 0} is CFL but NOT regular.
  • Not every CSL is context free. E.g., {aⁿbⁿcⁿ | n ≥ 1} is CSL but NOT CFL.
1.10 Practice Questions
Short Answer / Definition Questions
1

Define: Symbol, Alphabet, String, Language. Give one example of each.

Answer: Symbol = smallest atomic unit (e.g. 'a'). Alphabet = finite set of symbols (e.g. Σ={a,b}). String = finite sequence of symbols from Σ (e.g. "aab"). Language = any subset of Σ* (e.g. L = all strings over {a,b} of even length).
2

For Σ = {0, 1}, list all strings in Σ² and Σ³.

Answer: Σ² = {00, 01, 10, 11} (4 strings). Σ³ = {000, 001, 010, 011, 100, 101, 110, 111} (8 strings). |Σᵏ| = 2ᵏ.
3

What is the difference between Σ* and Σ⁺? What if Σ = ∅?

Answer: Σ* includes ε (empty string), Σ⁺ does not. Σ⁺ = Σ* − {ε}. If Σ = ∅: Σ* = {ε}, Σ⁺ = ∅.
4

What is a grammar? Define the 4-tuple and explain each component.

Answer: Grammar G = (V, T, P, S). V = Variables/Non-terminals (symbols that can be replaced). T = Terminals (actual language symbols, V ∩ T = ∅). P = Productions (rules α → β). S = Start symbol (S ∈ V). L(G) = all terminal strings derivable from S.
5

State the Chomsky Hierarchy. Name each type, the language it generates, and the automaton that accepts it.

Answer: Type 0 → Unrestricted Grammar → Recursively Enumerable Language → Turing Machine. Type 1 → CSG → Context Sensitive Language → LBA. Type 2 → CFG → Context Free Language → PDA. Type 3 → Regular Grammar → Regular Language → DFA/NFA.
6

What is the difference between Right Linear and Left Linear grammar? Give an example of each.

Answer: Right Linear: A → aB or A → a (non-terminal on RIGHT end). Left Linear: A → Ba or A → a (non-terminal on LEFT end). Right Linear example: S → aS | b. Left Linear example: S → Sa | b.

Identify the type of the following grammars (Type 0, 1, 2, or 3):

Long Answer / Conceptual Questions (Exam-Style)
13

Explain the Chomsky Hierarchy in detail. Draw the subset diagram showing the relationship between all four language classes.

Answer: Chomsky (1957) classified grammars into 4 types. Type 3 ⊂ Type 2 ⊂ Type 1 ⊂ Type 0. Each outer type strictly includes all inner types plus additional languages. Regular ⊂ CFL ⊂ CSL ⊂ RE. The innermost (Regular) is most restricted; outermost (Recursively Enumerable) is least restricted. [Draw concentric ellipses as shown in the diagram above.]
14

What is a Derivation Tree? State its properties and construct one for the string "aab" from S → aS | bS | a | b.

Properties: Root = S, leaves = terminals, internal nodes = non-terminals, production must exist for each parent-children set. Derivation: S → aS → aaS → aab. Tree has root S with children [a, S]; inner S with children [a, S]; innermost S with child [b].
15

How is Theoretical Computer Science applied in compiler design? Explain with reference to each compiler phase.

Answer: Lexical Analysis uses RE + DFA/NFA for token recognition. Syntax Analysis uses CFG + PDA for parsing. Semantic Analysis uses Attribute Grammars for type checking. Code Generation uses Turing Machine theory to understand computability limits. [Expand with the table from Section 1.8 for full marks.]

🎯 Exam Must-Remember Points
  • V ∩ T = ∅ — Variables and Terminals are always disjoint sets.
  • Σ* always includes ε; Σ⁺ never includes ε.
  • {ε} ≠ ∅ — language with empty string ≠ empty language.
  • Type 3 ⊂ Type 2 ⊂ Type 1 ⊂ Type 0 (proper subset at each level).
  • Regular Grammar = Right Linear OR Left Linear (not both mixed).
  • All DFAs are NFAs. Every NFA can be converted to an equivalent DFA.
  • RE = DFA = NFA = ε-NFA (all equivalent for regular languages).
  • CFG generates exactly Context Free Languages; accepted by PDA.
  • Language of a grammar L(G) = all terminal strings derivable from S.
  • Derivation tree root = S; leaves = terminals; internal = non-terminals.
