6.1 Introduction to Turing Machine
6.1.1 What is a Turing Machine?
Definition

A Turing Machine (TM) is a simple mathematical model of a general-purpose computer. It was proposed by Alan Turing in 1936 — before actual computers existed — to answer: "What can be computed?"

Key Facts
  • Most powerful automaton in Chomsky Hierarchy
  • Recognizes Recursively Enumerable Languages (Type 0)
  • Can simulate FA, PDA, and LBA
  • Can perform any computation a real computer can
  • May run forever (infinite loop) on some inputs
TM vs Previous Models
  • FA: Read-only, one-way movement
  • PDA: FA + stack (LIFO only)
  • TM: Read + Write, move both ways, infinite tape
  • TM can recognize aⁿbⁿcⁿ (PDA cannot)
  • Tape = unlimited general-purpose memory
Regular (FA) ⊂ CFL (PDA) ⊂ CSL (LBA) ⊂ Recursive (TM halts) ⊂ RE (TM may loop)
6.1.2 Block Diagram — Architecture
Figure 6.1 — TM Architecture. Finite Control reads/writes via head. Tape is infinite. Head reads current cell, can write new symbol and move L/R.
Three Components of TM
  • Finite Control: The "brain" — stores current state and transition rules.
  • Tape: Infinite in both directions. Initially has input surrounded by Blank (B) symbols. Head can READ and WRITE any cell.
  • Read/Write Head: Points to exactly one cell at a time. Can move Left (L), Right (R), or stay (N).
6.1.3 Formal Definition — 7-Tuple
Turing Machine — 7-Tuple

A Turing Machine is defined as: M = (Q, Σ, Γ, δ, q₀, B, F)

Symbol Name Description Important Constraints
Q States Finite, non-empty set of all states Q is finite
Σ Input Alphabet Finite set of input symbols B ∉ Σ (Blank not in input alphabet)
Γ Tape Alphabet Symbols that can appear on tape Σ ⊆ Γ, B ∈ Γ (all input symbols are tape symbols)
δ Transition Function δ: Q × Γ → Q × Γ × {L, R, N} Partial function — not all (q, X) pairs need transitions
q₀ Start State Initial state. q₀ ∈ Q TM begins in q₀ with head at leftmost input symbol
B Blank Symbol Empty cell marker. B ∈ Γ, B ∉ Σ All cells outside input contain B initially
F Final States Accepting states. F ⊆ Q TM halts and ACCEPTS when entering any state in F
TM vs PDA — Key 7-Tuple Difference

PDA is a 7-tuple (Q, Σ, Γ, δ, q₀, Z₀, F) where Z₀ is the initial stack symbol. TM is also a 7-tuple (Q, Σ, Γ, δ, q₀, B, F) where B is the Blank symbol. The 7th element is different — PDA has Z₀, TM has B.

6.1.4 Transition Function δ — In Detail
Transition Format

δ(q, X) = (p, Y, D) — In state q, reading symbol X: go to state p, write Y, move direction D.

Component Meaning
q Current state
X Symbol currently under the read/write head (from Γ)
p Next state to transition to
Y Symbol to WRITE on the tape, replacing X (can be same as X = no change)
D Direction: L (move left one cell), R (move right one cell), N (stay in place)
Transition Diagram Label Convention
  • On state diagram arrows, write: X / Y, D (Read X → Write Y, Move D)
  • Example: a / X, R means "read 'a', write 'X', move Right"
  • Example: 0 / 1, L means "read '0', write '1', move Left"
  • Example: B / B, N means "read Blank, write Blank, stay" (halt condition)
6.1.5 Instantaneous Description (ID) & Halting
ID Notation

A TM configuration is written as: α₁ q α₂ where α₁ = symbols to LEFT of head, q = current state, α₂ = symbol under head + symbols to its right.

ID Example

Tape: B a a b b B | Head on 2nd 'a' | State: q1

ID written as: a q1 abb (left of head = "a", head is on 'a', right = "bb")

After δ(q1, a) = (q2, X, R): ID becomes aX q2 bb

When TM ACCEPTS
  • Enters any state in F (final state)
  • TM halts immediately
  • Input string w is in L(M)
When TM REJECTS
  • Enters a non-final state where no transition is defined (crashes)
  • OR runs forever (infinite loop)
  • For recursive languages: always halts
  • For RE languages: may loop on rejection

P2
TM for L = {aⁿbⁿcⁿ | n ≥ 1}
This language is NOT context-free — PDA cannot recognize it — but TM CAN!

Strategy: Three-phase marking. Mark one 'a'→X, scan right for one 'b'→Y, scan right for one 'c'→Z. Return to start. Repeat until all marked. Accept when all symbols are X/Y/Z.

Figure P2 — TM for aⁿbⁿcⁿ. Three marking phases: a→X, b→Y, c→Z. Only TM can do this — PDA cannot count three symbols simultaneously.

P3
TM for 1's Complement of Binary Number
Flip every bit: 0→1, 1→0. Input "1010" → Output "0101"

Strategy: Scan left to right. Flip each bit. Halt when Blank encountered.

Figure P3 — TM for 1's complement. Single state q0 flips 0→1 and 1→0. Accepts (halts) when Blank is read.
State Read Write Move Next Reason
q0 0 1 R q0 Flip 0 to 1, continue right
q0 1 0 R q0 Flip 1 to 0, continue right
q0 B B N q_acc End of input → ACCEPT
P4
TM to Add 1 to a Binary Number
Binary increment: "1010" → "1011", "0111" → "1000" (carry propagation)

Strategy: Go to rightmost bit. Flip LSB from 0→1 and halt (no carry). If LSB is 1→0 and move left (carry). Repeat left until 0 or left edge.

Figure P4 — TM to add 1 to binary. q0 seeks right end. q1 propagates carry leftward (1→0) until 0 found (→1, done) or left edge (→1, done).
State Read Write Move Next Reason
q0 0 0 R q0 Scan right past 0s
q0 1 1 R q0 Scan right past 1s
q0 B B L q1 Found right end, start incrementing
q1 0 1 N q_acc Flip 0→1, no carry, DONE
q1 1 0 L q1 Flip 1→0, carry, move left
q1 B 1 N q_acc Carry overflow: write 1 at MSB, DONE
Trace — "0111" → "1000"

q0 scans R: 0→0, 1→1, 1→1, 1→1, B → switch to q1 (move L).

q1 on '1': write 0, L → q1. On '1': write 0, L → q1. On '1': write 0, L → q1. On '0': write 1, N → q_acc.

Result: 1000 ✓ (7+1=8)

P5
TM for Balanced Parentheses
Check well-formed parens: ε, (), (()), ()() accepted; ), )(, (() rejected

Strategy: Find innermost "()" pair, replace with XX. Repeat. If any unmatched ')' or '(' remains, reject. Accept when all replaced.

Figure P5 — TM for balanced parentheses. Repeatedly finds inner "()" pair and marks both as X. Accepts when all are marked.
P6
TM to Multiply Binary Number by 2
Append '0' at right end: "101" (5) → "1010" (10)

Strategy: Multiplying binary by 2 = left shift = append 0 at LSB. Move to right end, write '0'.

Figure P6 — TM multiplies binary by 2. Just append '0' at right end. Simplest TM — only 2 states!
State Read Write Move Next Reason
q0 0 0 R q0 Skip 0, keep moving right
q0 1 1 R q0 Skip 1, keep moving right
q0 B 0 N q_acc Found end: write 0 (LSB), ACCEPT
P7
TM for L = {w ∈ {0,1}* | #0(w) = #1(w)}
Strings with equal 0s and 1s: ε, 01, 10, 0011, 0101, 1010 ...

Strategy: Match-marking. Find leftmost '0', mark as X. Scan right for '1', mark as Y. Scan left back. Repeat. Accept when all matched.

Figure P7 — TM for equal 0s and 1s. Same match-marking strategy as P1 but matching 0 with 1 instead of a with b.
P8
TM for L = {a(a+b)*} — Strings Starting with 'a'
Accept any non-empty string over {a,b} that starts with 'a'

Strategy: Check only the first symbol. If 'a' → accept (and verify rest is non-empty-ish, but actually just 'a' being first is enough). If 'b' or B → reject.

Figure P8 — TM for strings starting with 'a'. q0 checks only first symbol. If 'a' → scan rest → accept. If 'b' or empty → reject.
6.3 Variations of Turing Machines
Key Theorem

All variations of TM are computationally equivalent to the standard single-tape TM. They can all simulate each other — no variation is strictly more powerful. They may differ in efficiency/speed, but not in what they can compute.

Multi-Track TM
  • Single tape with multiple "tracks" (layers)
  • Each cell holds a TUPLE of symbols (one per track)
  • Head reads/writes ALL tracks simultaneously
  • Useful for: keeping original + working copy on different tracks
  • δ: Q × Γᵏ → Q × Γᵏ × {L,R,N} (k = number of tracks)
  • Equivalent to single-track TM
Multi-Tape TM
  • k separate tapes, each with its own independent R/W head
  • Each head moves independently
  • δ: Q × Γᵏ → Q × Γᵏ × {L,R,N}ᵏ
  • Useful for: one tape = input, another = output/workspace
  • Can simulate in O(t²) time on single-tape TM
  • Equivalent to single-tape TM in power
Non-Deterministic TM (NTM)
  • For same (state, symbol), multiple possible transitions exist
  • Accepts if ANY computation path leads to accept state
  • δ: Q × Γ → P(Q × Γ × {L,R,N})
  • Simulated by deterministic TM using BFS over all paths
  • Equivalent to deterministic TM in power
  • Related to P vs NP (efficiency, not power)
Multi-Dimensional TM (2D Tape)
  • Tape is a 2D grid (or k-dimensional grid)
  • Head moves in 4 directions: L, R, Up, Down
  • More intuitive for some problems
  • Can simulate image processing, matrix operations
  • Equivalent to single-tape TM
Variation Description More Powerful? Simulation
Multi-Track Multiple layers on single tape No Encode k-tuple per cell
Multi-Tape k separate tapes with independent heads No Interleave tracks on single tape
NTM Multiple choices per (state, symbol) No BFS/DFS over all computation paths
2D Tape Grid tape, 4-direction movement No Diagonalize grid onto 1D tape
Semi-Infinite Tape Tape extends only to the right No Interleave left/right on one tape
6.4 Universal Turing Machine (UTM)
Definition

A Universal Turing Machine (UTM) is a Turing Machine that can simulate the behavior of ANY other Turing Machine. It takes two inputs: (1) an encoding of the TM to simulate, and (2) the input string for that TM.

Figure 6.2 — Universal TM takes the TM description ⟨M⟩ and input w, then simulates M on w exactly.
Significance of UTM
  • UTM = theoretical foundation of stored-program computers
  • A real computer runs any program = UTM simulates any TM
  • TM Description = Program | Input data = Data
  • First "programmable" theoretical machine
  • Led to the design of actual computers (von Neumann architecture)
UTM vs Real Computer
  • Similarity: Both can run any algorithm on any data
  • Difference 1: Real computers have finite memory; UTM has infinite tape
  • Difference 2: Real computers have clock speeds; UTM has no time concern
  • Difference 3: UTM cannot handle OS-like unbounded input streams
  • Computationally, anything a real computer does, UTM can too
6.5 Church-Turing Hypothesis
The Church-Turing Thesis

"Everything that is algorithmically computable is computable by a Turing Machine."
Equivalently: The intuitive notion of "algorithm" equals the formal definition of "TM-computable."

Key Points
  • Proposed independently by Alan Turing (via TM) and Alonzo Church (via Lambda Calculus) in 1936.
  • It is a hypothesis (conjecture), NOT a theorem — it cannot be formally proven because "algorithmically computable" is an informal notion.
  • Every proposed alternative model of computation has been proven equivalent to TM — this is strong (but not conclusive) evidence.
  • If Church-Turing thesis is true, then TM is the ultimate model — nothing is more powerful.
Equivalent Models of Computation
Model Creator Year Equivalent to TM?
Turing Machine Alan Turing 1936 Yes (definition)
Lambda Calculus Alonzo Church 1936 Yes — proven
General Recursive Functions Kurt Gödel 1936 Yes — proven
Post Systems Emil Post 1943 Yes — proven
Register Machines — — Yes — proven
Markov Algorithms Andrey Markov — Yes — proven
6.6 The Halting Problem
Definition

Halting Problem: Given a Turing Machine M and an input w, does M eventually halt when run on w?

Decision version: Is there an algorithm (TM) that correctly answers YES/NO for ALL possible (M, w) pairs?

The Halting Problem is UNDECIDABLE

Alan Turing proved in 1936 that NO Turing Machine (hence no algorithm) can solve the Halting Problem for all inputs. This is one of the most profound results in computer science — it shows fundamental limits of computation.

Proof by Contradiction (Diagonalization)
1
Assume there exists a TM H that solves the Halting Problem:
H(⟨M⟩, w) = "HALT" if M halts on w.
H(⟨M⟩, w) = "LOOP" if M loops forever on w.
2
Construct a new TM D (the "diagonalizer"):
D takes ⟨M⟩ (encoding of any TM M) as input.
D runs H(⟨M⟩, ⟨M⟩) — asks H if M halts on its OWN description.
If H says "HALT" → D goes into an INFINITE LOOP.
If H says "LOOP" → D HALTS and accepts.
3
Run D on ⟨D⟩ itself (give D its own description as input):
Case 1: If D halts on ⟨D⟩ → H says "HALT" → D loops. CONTRADICTION.
Case 2: If D loops on ⟨D⟩ → H says "LOOP" → D halts. CONTRADICTION.
4
Conclusion: Both cases lead to contradiction. Our assumption (H exists) is FALSE. The Halting Problem is UNDECIDABLE. □
Figure 6.3 — Halting Problem Diagonalization. D uses H as a subroutine. When D is fed its own description ⟨D⟩, both outcomes lead to contradiction.
Significance of Undecidability
  • There exist well-defined mathematical questions that no algorithm can answer.
  • The Halting Problem is RE (recursively enumerable) but NOT recursive — we can verify acceptance but cannot always verify rejection.
  • Many real-world problems (virus detection, program equivalence) are reducible to the Halting Problem → also undecidable.
  • This does NOT mean we can't solve specific instances — just that no general algorithm exists.
6.7 Power of TM over PDA
Feature PDA (Pushdown Automaton) Turing Machine
Memory Type Stack (LIFO only) Infinite tape (random access)
Memory Access Only TOP of stack Any cell on tape (read AND write)
Tape movement Input: left→right only Both left AND right freely
Languages Context Free Languages (Type 2) Recursively Enumerable (Type 0)
Recognizes aⁿbⁿcⁿ? ✗ No ✓ Yes
Recognizes aⁿbⁿ? ✓ Yes ✓ Yes
Simulate FA? ✓ Yes ✓ Yes
Simulate PDA? — ✓ Yes
Simulate TM? ✗ No — (itself)
Always halts? Yes (on finite input) May loop forever
Why TM is More Powerful than PDA
  • Read AND Write: TM can modify the tape; PDA can only read input (and push/pop stack).
  • Two-way movement: TM head can move left freely; PDA input is read left-to-right only.
  • General memory: TM tape = unrestricted random access; PDA stack = LIFO only.
  • Multiple stacks: TM tape effectively acts as unlimited stacks. Two-stack PDA = TM.
6.8 Recursive and Recursively Enumerable Languages
Recursive Language (Decidable)
  • TM HALTS on EVERY input
  • For w ∈ L: TM halts and ACCEPTS
  • For w ∉ L: TM halts and REJECTS
  • Always gives a definitive answer
  • Examples: All regular languages, CFLs, aⁿbⁿcⁿ
  • Also called: Decidable languages
Recursively Enumerable (RE)
  • TM accepts every string in L
  • For w ∈ L: TM halts and ACCEPTS
  • For w ∉ L: TM may REJECT or LOOP FOREVER
  • Cannot always give a definitive NO answer
  • Example: Halting Problem (L(TM description, input) pairs)
  • Also called: Semi-decidable languages
Figure 6.4 — Language Hierarchy. Regular ⊂ CFL ⊂ CSL ⊂ Recursive ⊂ RE ⊂ All Languages. Halting Problem is RE but not Recursive.
Language Class Recognized By For w ∈ L For w ∉ L Example
Regular DFA/NFA Halts, accepts Halts, rejects a*, (a+b)*
Context Free PDA Halts, accepts Halts, rejects aⁿbⁿ, palindromes
Context Sensitive LBA Halts, accepts Halts, rejects aⁿbⁿcⁿ
Recursive TM (always halts) Halts, accepts Halts, rejects Halting problem for FA
RE TM (may loop) Halts, accepts May loop forever Halting Problem of TM
Non-RE No TM exists — — Complement of Halting Problem
6.9 Practice Questions
TM Design Questions
1

Design a TM for L = {aⁿbⁿcⁿ | n ≥ 1} and show the complete ID trace for input "aabbcc".

Use P2 design. Trace for "aabbcc":
q0: a→X,R → q1 | q1: a→a,R, b→Y,R → q2 | q2: b→b,R, c→Z,L → q3 | q3: scan ← to X → q0
Round 1: XaYbZc. Round 2: XXYYZZc... wait: XaYbZc then q3 scans left to X, q0 moves right: sees a→X,R...
After 2 rounds: XXYYZZ → q0 sees Y → q4 → skip Y,Z → B → ACCEPT
2

Design a TM that computes the 2's complement of a binary number.

2's complement = flip all bits then add 1.
Step 1: Scan right to end. Step 2: Scan left — copy trailing 0s as 0s, copy first 1 as 1. Step 3: After first 1, flip all remaining bits (1→0, 0→1).
States: q0 (go right), q1 (hit B, go left), q2 (copy trailing 0s and first 1), q3 (flip remaining), q_acc.
q2: 0/0,L → q2 | 1/1,L → q3 | q3: 0/1,L → q3 | 1/0,L → q3 | B/B,R → q_acc.
3

Design a TM for addition of two unary numbers. Input: 1ᵐ 0 1ⁿ (separator 0). Output: 1ᵐ⁺ⁿ.

Strategy: Replace the '0' separator with '1'. Then erase the last '1' (to keep m+n total).
q0: scan right past 1s. q0 on 0: write 1, R → q1. q1: scan right past 1s. q1 on B: write B, L → q2. q2: erase last 1 (write B) → q_acc.
Example "111 0 11" → "111 1 11" → erase last 1 → "111 1 1" = 11111 (5 = 3+2) ✓
4

Design a TM to check if a binary string is a palindrome. Show transitions.

Strategy: Compare first and last symbols. Mark both if equal. Repeat.
q0: read first symbol (0 or 1), erase it (→B), remember in state, go right to find last symbol.
q1 (remembered 0): skip non-blank, on B go left, if last = 0 erase (→B, L) → q4 else reject.
q1 (remembered 1): same but check last = 1.
q4: scan left to leftmost non-blank B → q0. Accept when q0 sees B (all erased → palindrome).
Theory Questions
5

What are Recursive and Recursively Enumerable Languages? Give examples and explain the difference.

Recursive (Decidable): TM halts on ALL inputs. Accepts L, rejects L̄. Algorithm always terminates. Example: aⁿbⁿcⁿ, all CFLs.
RE (Semi-decidable): TM accepts L, may loop on strings not in L. No guarantee of rejection. Example: Halting Problem L_TM = {⟨M,w⟩ | M halts on w}.
Key difference: Recursive → TM is a decider. RE → TM is a recognizer only.
6

State and explain the Church-Turing Thesis. Why is it a hypothesis and not a theorem?

Thesis: "Everything algorithmically computable is computable by a TM."
Why hypothesis: "Algorithmically computable" is an informal, intuitive notion — it cannot be formally defined. A theorem requires a formal proof from formal premises. Since one side (intuition of algorithm) is informal, no formal proof can bridge the gap.
Evidence (not proof): All proposed alternative models (Lambda Calculus, recursive functions, Post systems, Markov algorithms) have been proven equivalent to TM. This universal agreement strongly suggests the thesis is true.
7

Explain the Halting Problem. Provide the diagonalization proof of undecidability.

Problem: Given ⟨M⟩ and w, does M halt on w? Answer: NO algorithm can decide this.
Proof: Assume H exists. Build D: D(⟨M⟩) = loop if H(⟨M⟩,⟨M⟩)="halt", halt if H(⟨M⟩,⟨M⟩)="loop". Run D(⟨D⟩): if D halts → H says halt → D loops. If D loops → H says loop → D halts. Both cases contradict → H cannot exist → HP is undecidable. □
8

What is a Universal Turing Machine? How does it relate to modern computers?

UTM: A TM that simulates any other TM M on input w, given ⟨M⟩ (encoding of M) and w.
Relation to computers: A real computer is a physical realization of a UTM — it takes a program (≈TM description) and data (≈input) and executes (≈simulates). The stored-program concept (von Neumann) comes directly from UTM. Anything a real computer computes, a UTM can too (ignoring finite memory constraints).
9

Are Multi-Tape TMs more powerful than single-tape TMs? Prove or disprove.

NO — they are equivalent in computing power.
Proof sketch (Multi-tape → Single-tape simulation): Given a k-tape TM M, simulate it on a single-tape TM M' as follows: M' uses a single tape with 2k tracks (via interleaving) — k tracks for tape content and k tracks for head positions (markers). Each step of M is simulated by M' making multiple passes to update all k tracks. M' takes O(t²) steps to simulate t steps of M. Since M' correctly simulates M, if M accepts/rejects, so does M'. □

  • TM is 7-tuple. Different from PDA's 7-tuple — TM has B (blank), PDA has Z₀ (initial stack).
  • Transition label on diagrams: X / Y, D (read X, write Y, direction D).
  • aⁿbⁿ: 4 states (q0 mark a, q1 scan for b, q2 scan back, q3 verify). aⁿbⁿcⁿ: 5 states — only TM can do it!
  • 1's complement: simplest TM — 1 state, just flip bits. Multiply by 2: 2 states, append 0.
  • All TM variations (multi-track, multi-tape, NTM) are EQUIVALENT — no more powerful than standard TM.
  • UTM = stored-program computer. Takes ⟨M⟩ (program) and w (data), runs M on w.
  • Church-Turing is a HYPOTHESIS (not theorem) — "algorithm" is informal, can't be formally proven.
  • Halting Problem is UNDECIDABLE — proven by diagonalization. But it IS Recursively Enumerable.
  • Recursive = TM always halts (decider). RE = TM may loop on non-members (recognizer only).
  • Complement of Halting Problem is NOT even RE — cannot be recognized by any TM.
