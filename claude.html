Q1a
Key Applications of Theoretical Computer Science
[5]
What are the key applications of Theoretical Computer Science?
Answer
  • Compiler Design: Lexical analysis uses DFA/NFA to tokenize source code via regular expressions. Syntax analysis (parsing) uses CFG and PDAs. Every compiler is built on TCS.
  • Text Search & Pattern Matching: grep, regex engines, search engines — all based on finite automata and regular expressions.
  • Network Protocols: Protocol state machines modelled using FA (TCP handshake, HTTP states).
  • AI & NLP: Formal grammars model language; parsers in NLP use CFL/PDA techniques.
  • Computability Limits: Halting Problem and undecidability show what computers fundamentally CANNOT do — critical for security analysis.
  • Cryptography: Complexity theory (P vs NP) is the mathematical foundation of modern cryptographic security.
  • Software Verification: Model checkers use automata to verify program correctness automatically.

CFG Ambiguity — S→a|iCtS|iCtSeS, C→b (if-then-else)
[10]
CFG: S→a|iCtS|iCtSeS, C→b. Use "ibtibtaea" for LMD, RMD, derivation trees. Analyze ambiguity.
Answer

This models the if-then-else construct: i=if, t=then, e=else, C=condition(→b), a=statement. String "ibtibtaea" = if b then (if b then a) else a — the classic dangling-else problem.

Leftmost Derivation 1 (else binds to INNER if — standard interpretation):

S ⇒ iCtS (S→iCtS, outer if-then without else) ⇒ iCtiCtSeS (inner S→iCtSeS) ⇒ ibtiCtSeS (C→b) ⇒ ibtibtSeS (C→b) ⇒ ibtibta eS (S→a) ⇒ ibtibtaea (S→a) ← "if b then (if b then a else a)"

Leftmost Derivation 2 (else binds to OUTER if):

S ⇒ iCtSeS (S→iCtSeS, outer if-then-else) ⇒ iCtiCtSSeS ... (different parse tree structure) (Different binding gives different derivation trees → AMBIGUOUS)

Conclusion: Grammar is AMBIGUOUS — the string "ibtibtaea" has two distinct parse trees. The ambiguity arises from the dangling else problem: the grammar does not specify which 'if' the 'else' belongs to when there is a nested if-then without else.

Cause: The production S→iCtS (if-then without else) followed by S→iCtSeS (if-then-else) allows the same string to be parsed with the 'else' attached to either the outer or inner 'if'.

Remedy: Distinguish "matched" statements (with else) from "unmatched" (without). Rewrite grammar to force else to bind with nearest unmatched if.

Recursive & RE Languages + TM for Unary Increment
[10]
Define and explain Recursive and RE languages with examples. Give TM for unary increment. Input: 00000 → Output: 000000.
Recursive Language (Decidable)

A language L is recursive if there exists a TM that halts on EVERY input and correctly accepts strings in L and rejects strings not in L. Always gives a YES or NO answer.

  • For w ∈ L: TM halts and ACCEPTS
  • For w ∉ L: TM halts and REJECTS
  • Examples: All regular languages, all CFLs, aⁿbⁿcⁿ (recognized by TM that always halts)
Recursively Enumerable (RE) Language

A language L is RE if there exists a TM that accepts every string in L but may loop forever on strings not in L.

  • For w ∈ L: TM halts and ACCEPTS
  • For w ∉ L: TM may REJECT or LOOP FOREVER (no guarantee!)
  • Example: The Halting Problem — can verify a TM halts on input (if it does), but cannot always detect non-halting
  • Recursive ⊂ RE — every decidable language is RE but not vice versa
TM for Unary Increment (Input: 00000 → Output: 000000)

In unary, number n = n zeros. Incrementing n by 1 = appending one more zero.

Arden's Theorem — Derive RE from DFA
[10]
State Arden's Theorem. Derive RE for DFA: q1→a→q2, q1→b→q3, q2→a→q3, q3→a→q3. Start: q1, Final: q3.
Arden's Theorem
Theorem
If P and Q are regular expressions and ε ∉ P, then the equation R = Q + RP has a unique solution: R = QP*
Step 1 — Write State Equations

For each state qᵢ write: qᵢ = ε (if start) + Σ (qⱼ·symbol) for all transitions qⱼ→symbol→qᵢ

q1 = ε (q1 is start state) q2 = q1·a (only q1→a→q2) q3 = q1·b + q2·a + q3·a (q1→b, q2→a, q3→a all go to q3)
Step 2 — Substitute q2 into q3
q3 = q1·b + (q1·a)·a + q3·a = q1·(b + aa) + q3·a
Step 3 — Apply Arden's Theorem

This is R = Q + R·P form where R=q3, Q=q1·(b+aa), P=a. So:

q3 = q1·(b+aa)·a* = ε·(b+aa)·a* (since q1 = ε) = (b+aa)a*
Result — RE for L(M)
L = (b + aa)a* = ba* + aaa*

Language: strings that either start with 'b' followed by any a's, OR start with "aa" followed by any a's. In other words, strings of the form ba* or a²a* = aa⁺.

CNF Conversion — G: S→AACD, A→aAb|ε, C→aC|a, D→aDa|bDb|ε
[10]
CFG G: S→AACD, A→aAb|ε, C→aC|a, D→aDa|bDb|ε. Transform to CNF.
Step 1 — Find Nullable Symbols

Nullable: A (A→ε), D (D→ε). Check S: not directly nullable (AACD needs all ≥ 1 symbol from each unless A and D nullable).

Step 2 — Remove ε-Productions

For S→AACD, A appears at positions 1,2; D appears at position 4. Enumerate subsets of removing nullable symbols (A and D, but not both leaving nothing):

S → AACD | ACD | AAC | CD | AC | C A → aAb | ab (from aAb removing A) C → aC | a D → aDa | bDb | aa | bb (removing D from aDa, bDb)
Step 3 — Remove Unit Productions

S→C is unit. Replace with C's productions: add S→aC, S→a. Remove S→C.

Step 4 — Replace Terminals in Multi-Symbol RHS

Create: Xa→a, Xb→b for each terminal in mixed productions.

A → XaE1 where E1 → AXb (from aAb → Xa·A·Xb, break into Xa·E1, E1→A·Xb) A → XaXb (from ab) C → XaC (from aC → already binary with new NT) D → XaE2 where E2 → DXa (from aDa) D → XbE3 where E3 → DXb (from bDb) D → XaXa | XbXb (from aa, bb) Xa → a | Xb → b
Step 5 — Break Long S Productions into Binary
S → AF1 where F1 → AF2 where F2 → CD (from AACD) S → AF2 (from ACD) S → AF3 where F3 → AC (from AAC) S → CD | AC | aC | a
Final CNF Summary
All productions are now A→BC or A→a form. Key new non-terminals: Xa, Xb, E1, E2, E3, F1, F2, F3. Every terminal in a multi-symbol RHS is replaced by its corresponding Xa/Xb non-terminal. All RHS with 3+ symbols are broken into binary using new intermediate non-terminals.
Q6a
Pumping Lemma — Prove aⁿbⁿ and aⁿbⁿcⁿ are NOT Regular
[10]
Check regularity using Pumping Lemma: (i) L={aⁿbⁿ|n≥1}, (ii) L={aⁿbⁿcⁿ|n≥1}.
Pumping Lemma for Regular Languages
Statement
If L is regular with pumping length n, then ∀w∈L with |w|≥n, ∃ decomposition w=xyz such that: (1) |y|>0, (2) |xy|≤n, (3) ∀i≥0: xyⁱz ∈ L.
(i) L = {aⁿbⁿ | n≥1} — NOT Regular
Proof by Contradiction
1
Assume L is regular with pumping length p.
2
Choose w = aᵖbᵖ ∈ L. |w| = 2p ≥ p ✓
3
Since |xy| ≤ p, both x and y consist ONLY of a's. Let y = aᵏ (k > 0).
4
Pump down: i=0 → xy⁰z = xz = aᵖ⁻ᵏbᵖ. Since k>0, #a < #b → xz ∉ L.
5
Contradiction! Assumption wrong. L = {aⁿbⁿ} is NOT regular. □
(ii) L = {aⁿbⁿcⁿ | n≥1} — NOT Regular
Proof by Contradiction
1
Assume L is regular with pumping length p.
2
Choose w = aᵖbᵖcᵖ ∈ L. |w| = 3p ≥ p ✓
3
Since |xy| ≤ p, the substring y lies entirely within the a-section. y = aᵏ, k > 0.
4
Pump up: i=2 → xy²z = aᵖ⁺ᵏbᵖcᵖ. More a's than b's and c's → ∉ L.
5
Contradiction! L = {aⁿbⁿcⁿ} is NOT regular. □
Additional Note
L={aⁿbⁿcⁿ} is also NOT context-free — proven by CFL Pumping Lemma. It is Context-Sensitive (Type 1), recognized only by Linear Bounded Automata (LBA). TM can recognize it using three-phase marking (mark a→X, b→Y, c→Z repeatedly).

Q7c — Universal Turing Machine (UTM)

A UTM is a TM U that can simulate any TM M on any input w, given ⟨M⟩ (encoding of M) and w as its own input. U(⟨M⟩, w) behaves exactly like M(w).

  • Foundation: UTM is the theoretical basis of the stored-program computer
  • Analogy: UTM = general-purpose computer; ⟨M⟩ = software program; w = data input
  • Von Neumann architecture directly implements the UTM concept
  • Any computation a real computer performs, a UTM can simulate (ignoring speed/memory limits)
Q7d — Formal Language

A formal language L over alphabet Σ is any subset of Σ* defined by precise mathematical rules (grammar, automaton, or RE) — unlike natural languages which are informal and ambiguous.

Formation: 1) Define Σ = {a,b}, 2) Σ* = all finite strings over Σ, 3) Pick a subset by a rule. Example: L = {w∈{a,b}* | w starts and ends with 'a'} is a formal language defined by RE: a(a+b)*a + a.

(i) Union of two non-regular cannot be regular. (ii) L((ab*ba*)∩(ba*ab*))=ε. (iii) Intersection of two CFLs is never context free. (iv) L={1ⁿ:n≤1000,n prime} DFA may have fewer than 900 states. (v) Every finite subset of Σ* is regular.

(i) FALSE. The union of two non-regular languages CAN be regular. Counterexample: L1 = {aⁿbⁿ | n≥0} (non-regular) and L2 = its complement {a,b}* \ {aⁿbⁿ} (also non-regular). Their union = {a,b}* which IS regular. The class of non-regular languages is not closed under union.

(ii) TRUE. ab*ba* describes strings starting with 'a' ending with 'a' (at least "aba"). ba*ab* describes strings starting with 'b' ending with 'b'. No string can start with both 'a' and 'b' → intersection is empty (∅). So L(...)∩L(...) = ∅. If the statement means empty language (∅), then TRUE.

(iii) FALSE. The intersection of two CFLs is NOT always non-context-free. For example, {aⁿbⁿ | n≥0} ∩ {aⁿbⁿ | n≥0} = {aⁿbⁿ | n≥0} which IS a CFL. It is true that CFLs are NOT closed under intersection (intersection of two CFLs may not be CFL), but "never context free" is too strong — it is sometimes CFL and sometimes not.

(iv) TRUE. L = {1ⁿ | n≤1000 and n is prime} is a FINITE language (there are 168 primes ≤1000). Every finite language is regular and can be accepted by a DFA with at most 1002 states (one per length 0..1001, plus dead state). 1002 < 900 is false — it needs ~1002 states. Actually: a minimal DFA can use 1001 states (lengths 0..1000) plus a trap state = 1002. But the statement says "may have FEWER than 900 states" which is FALSE since we need at least ~168 accept states. Actually, the minimal DFA for this language needs states for each length from 0 to 1001 (reject dead states can be merged) — around 1001 states minimum. So the statement is FALSE.

(v) TRUE. Every finite language L = {w₁, w₂, ..., wₖ} is regular. RE: w₁+w₂+...+wₖ (finite union of finite strings). Each wᵢ is a concatenation of symbols (each regular), finite union preserves regularity. Also, every finite language is accepted by a DFA (which can always be constructed for any finite set of strings).

Q1a
Formal Language and Finite Automata
[5]
What do you understand by formal language and finite automata? Explain.
Formal Language

A formal language L over alphabet Σ is any subset of Σ* (the set of all finite strings over Σ) defined by precise mathematical rules — unlike natural languages which are informal and ambiguous.

  • Alphabet Σ: finite set of symbols, e.g. {0,1} or {a,b,c}
  • String: finite sequence of symbols from Σ, including ε (empty string)
  • Σ*: set of ALL possible strings over Σ (infinite set)
  • Language L ⊆ Σ*: any subset of Σ* defined by a grammar, RE, or automaton
  • Example: Σ={a,b}, L={aⁿbⁿ|n≥0} = {ε, ab, aabb, ...} is a formal language
Finite Automaton

A Finite Automaton (FA) is an abstract machine with a finite number of states that reads symbols one by one and accepts or rejects a string based on its final state.

  • DFA (Deterministic FA): exactly one transition per (state, symbol). 5-tuple (Q,Σ,δ,q0,F).
  • NFA (Non-deterministic FA): zero or more transitions per (state, symbol).
  • ε-NFA: NFA with ε-transitions (moves without consuming input).
  • FA recognizes exactly Regular Languages (Type 3 — Chomsky). DFA = NFA = ε-NFA in power.
  • FA without output: just accepts/rejects. FA with output: Mealy or Moore machine produces output symbols.

A Regular Expression (RE) is a formal notation to describe Regular Languages using: individual symbols, union (+), concatenation (·), Kleene star (*). Every RE corresponds to exactly one regular language.

English: All strings over {a,b} that contain exactly two a's. Any number of b's (including zero) can appear before the first 'a', between the two a's, and after the second 'a'. Example strings: "aa", "bab", "abba", "babab".

English: All strings over {a,b} that contain at least one double letter — either "aa" or "bb" as a consecutive substring. Example: "aab", "abba", "bba", "abb". Strings like "ab", "ba", "abab" do NOT qualify.

R3 = a(a+b)*a

English: All strings over {a,b} that start with 'a' AND end with 'a' and have length ≥ 2. The middle (a+b)* can include anything including ε, giving "aa" as shortest. Example: "aa", "aba", "abba", "aaba".

Universal Turing Machine & Halting Problem
[10]
Write short note on: (i) Universal Turing Machine. (ii) Halting Problem.
(i) Universal Turing Machine (UTM)

A Universal Turing Machine U is a TM that can simulate ANY other TM M on any input w, given ⟨M⟩ (an encoding of M's description) and w as its input.

  • Input: ⟨M⟩ (description of TM M) concatenated with w (input for M)
  • Behavior: U(⟨M,w⟩) accepts iff M accepts w; rejects/loops iff M rejects/loops on w
  • Foundation: UTM is the theoretical model behind stored-program computers (von Neumann architecture)
  • Significance: Shows that a single fixed machine can perform ANY computation — just change the program (⟨M⟩), not the machine
  • Analogy: UTM = general-purpose computer; ⟨M⟩ = software; w = data input
(ii) Halting Problem

Problem: Given TM M and input w, does M halt (reach a final state) when run on w?

Theorem (Turing, 1936): The Halting Problem is UNDECIDABLE — no algorithm can solve it for all inputs.

Proof Sketch (Diagonalization)
1
Assume TM H exists: H(⟨M⟩,w) = "halt" if M halts on w; "loop" if M loops on w.
2
Construct TM D: D(⟨M⟩) = IF H(⟨M⟩,⟨M⟩)="halt" THEN loop ELSE halt.
3
Run D on ⟨D⟩: If D halts on ⟨D⟩ → H says "halt" → D loops. CONTRADICTION. If D loops → H says "loop" → D halts. CONTRADICTION.
4
Both cases contradict → H cannot exist → Halting Problem is undecidable. □

Significance: Shows fundamental limits of computation — some well-defined mathematical questions have no algorithmic solution.
